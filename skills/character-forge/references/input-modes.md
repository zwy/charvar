# 输入模式与基准职责

## 1. 两条主线入口

同一份角色资产提供两个**独立**入口。身份来源、允许变化、禁止混用项和测试状态都分别标注，不互相借用。

### 模式 A：固定角色延续

目标：继续生成同一个角色。

| 项 | 规定 |
|---|---|
| 身份来源 | 获用户认可的基准图（全身正面基准为默认） |
| 基准负责 | 脸部辨识度、体态、可见造型 |
| 文字负责 | 设定确认、不可见结构、本轮变化 |
| 场景变量 | 表情、姿态、镜头、环境——不进入永久身份前缀 |
| 终端输入 | 认可基准图（已存在则复用） |

- 新场景优先使用认可基准，不默认切回纯文字。
- 纯文字重建可提供为**可选**入口，必须标明不能据此保证精确恢复原角色身份。
- 发生基准冲突时指定唯一身份优先来源，不要求模型平均融合。

### 模式 B：用户照片扮演

目标：保留上传者个体身份，套用角色的服装、造型方向、画风或场景。

| 项 | 规定 |
|---|---|
| 身份来源 | 上传者自己的照片（终端默认单张） |
| 照片负责 | 脸、个体身份、肤色、年龄感 |
| 文字资产负责 | 服装、造型方向、画风、场景 |
| 平台引用 | 抖音「素材1」；视频号「#图1」 |
| 输出结构 | 可固定，脸和个体特征随上传者变化 |

- 不把固定角色的脸型、眼色、肤色、体型清单直接作为上传者的强制属性。
- 发型、妆容、体态、配饰哪些保留、哪些转换，逐项明确。不笼统写「保持所有特征」又要求全部换造型。
- 终端默认就是一张照片，不隐含要求上传第二张角色图。开发阶段若需要参考角色图，那是开发阶段的输入，不得偷渡成终端默认要求。
- 用户扮演的完整待测提示词可以先交付，不阻塞固定角色的正式资产交付。

### 状态互不借用

两项角色基础图被认可，只证明相应的固定角色开发轮次获得认可。两种模式分别标注状态，文档标题不得暗示两者都已验证。

## 2. 开发阶段的其他输入形态

| 形态 | 身份来源 | 风格来源 | 主要边界 |
|---|---|---|---|
| 纯文字新建 | 文字设计 | 用户指定风格或可复用模块 | 无图时不要求对齐参考 |
| 参考图角色提取 | 图中角色 | 原风格或明确替换 | 不继承无关背景和对白 |
| 已有角色延续 | 认可角色基准 | 当前分支 | 不重新设计脸或体态 |
| 跨媒介换风格 | 旧图提供设计，认可新图后新图优先 | 新分支媒介 | 旧线条或比例不强行照搬 |

## 3. 单图优先不是绝对单图

角色开发阶段默认尽量用职责清楚的一张图，缺失部分按已确认文字补全。确实需要双图时，各自明确身份、服装或构图职责。

抖音特效的终端用户通常以一张照片进入。模式 B 的终端默认输入就是单张照片；开发阶段的多图能力不得写成终端默认要求。

## 4. 常见参考职责

- 身份：面部关系、肤色、年龄感、个体特征。
- 全身：体态、头身比例、衣服层次与鞋履。
- 风格：媒介、笔触或摄影质感，不默认携带参考人物的脸。
- 服装：剪裁、配色、材质与装饰，不带模特身份。
- 姿势／构图：关节与支撑、镜头、位置，不带另一张脸。
- 多视图：同一个角色的多个观察方向，不是多个人物。

参考图没有展示的部位不能据此声称已知。全身图和半身图出现身份冲突时指定优先级或先修正，不要求模型平均融合。

**输入职责的显式说明。** 半身图未展示的下身、鞋履和侧背结构，必须明确由哪一项提供：已认可的全身基准、用户文字设定，还是设计补全。不能让下一位 Agent 猜。

## 5. 缺图处理

- 基准图缺失时，明确写「用户侧已生成，尚未归档／尚未提供给助手」，请求用户补充，不写「未产生」。
- 不伪造文件名、路径或可访问链接。
- 缺少关键基准时，说明该图负责什么、取得方式是什么，以及在此之前可以推进到哪一步。
- 文档索引（如 R1、R2）是文档内部编号，不是平台素材 ID，不与「素材1」「#图1」混用。

## 6. 新风格分支

1. 记录旧分支当前认可设计。
2. 列出保留：身份特征方向、服装、标志性外观等。
3. 列出转换：线条、材质、比例夸张、光影、发丝或皮肤表现等。
4. 生成新分支定妆，等待用户反馈。
5. 用户认可后指定新风格身份基准；后续优先用它继续。
6. 旧分支保留，变动共同服装时明确是否同步两边。

不能同时要求严格保持插画五官比例与自然真人比例；应明确按真人结构转译并保留识别方向。

## 7. 身份模式优先级

已经有真人基准时，泛化文字（例如「小巧鼻子」）仅用于描述该人，不能据此重新选脸。角色姓名不是身份参考。
用户照片扮演与固定角色是不同任务，分别测试；用户年龄感、性别表达、肤色、发型和体态不因套装而擅自改变。

## 8. 预留扩展

双主体：各自身份、数量、相对尺度、位置、遮挡与接触。
视频：首帧基准、初始状态、一个主要动作、结束状态、时序与道具连续性。
以上仅为未来入口，不是当前版本已经实现或验证的流程。
