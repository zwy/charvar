# 语言、长度与字符预算

## 1. 输出语言跟随用户

- 用户用中文沟通 → 提示词用中文写作。
- 用户用其他语言沟通 → 提示词用英文写作。
- 判据是本轮对话的主要沟通语言，不随参考图内容或提示词里引用到的语言改变。
- 用户明确要求换语言时按用户要求，并在记录里写明实际使用的语言。
- 两种语言的提示词分别保存、分别记录字符数与复测状态，不互相借用通过记录。
- 不因原提示词是英文而自动让整个项目继续英文。
- 获认可的英文原文仍按原样保留；中文整理版单独标为新版本，不顶替原文。

## 2. 平台硬上限

- 长度以目标平台明示的字符上限为准。上限是硬边界，超出即无法提交，不是「尽量接近」。
- 已知默认值：**即梦 2000 字符**（带参考图的 image2image）。该值来自用户的使用约束，是当前项目的默认预算，不是平台的永久官方承诺；平台调整后以新值为准。
- 即梦**纯文生图（text2image）上限约 1600 字符**，与 image2image 不是同一个数。S1 全身正面定妆这类没有参考图的提交按 1600 算，不要拿 2000 去写。
- 平台未指定时明确写出预算来源（「本次任务给定 2000」「平台未提供上限，本轮未设硬上限」），不默认其他平台同样 2000。
- 交付前用 `scripts/prompt_budget.py` 按实际预算校验。`--strict` 超限返回 1，属交付失败，不得标为合规。
- 平台实际计数口径（是否计空格、换行、标点）未经验证。校验以本地 `len` 为准；平台拒收时以平台为准，并把差异记入项目状态。

## 3. 计数口径

- 按 Python `len` 统计 Unicode 码点，包含正文中的空格与换行，不含 Markdown 围栏与围栏外的说明文字。
- 总字符数统计**完整提交稿**，包括参考说明、身份、场景、对白、限制、空格和换行。
- 字符数、token 数与价格是三件事，不互相换算。**不把字符长度说成费用。**
- 不提供固定的「中文↔英文等价倍率」。需要判断长度时直接实际计数。

如果保留了历史经验估算，只能写成：样本范围（几组中英对照）、仅供估算参考、不作计费依据、不作硬门槛。不作为流程中的默认换算步骤。

## 4. 超限时的压缩顺序

超限时按顺序压缩，命中即停，不要连跳：

1. 删重复表达、修饰性形容词、同义并列词。
2. 删次要背景与次要道具，保留识别所需的最小场景信息。
3. 删画外信息：当前景别不出现的内容（头肩图不需要裤脚、鞋袜、脚尖朝向；影响上身轮廓的肩带等除外）。
4. 压句式：拆长句、去掉从句与嵌套修饰，用短语或逗号并列代替完整句。
5. 改用精简版固定前缀（与正常版共享同一套关键设定，只是压缩重复表达）。
6. 最后才动身份与服装关键结构——这些不能删，删了就不是同一角色了。

压缩不得改变设定含义。压缩后重新计数、重新校验。

**拆分提交意味着工作流变化。** 一次图片任务不能简单靠把提示词拆成两次提交就宣称仍是同一条任务。拆分时明确说明工作流已改变，两次提交各自独立记录与计状态。

## 5. 档案完整性与景别化提交稿分离

- 角色档案完整保存头脸、体态、服装、配件及侧背设定。
- 单次提交根据景别选择相关内容，不机械抄写全部设定。
- 从提交稿中删去画外描述，不等于从角色档案中删除该设定；档案仍完整保留。

## 6. 混合写法的处理

用中文承载结构化描述、只保留少量英文风格或画质关键词，是一种常见做法。

- 属待验证方案，**不是**已确认可用。实际响应由目标模型决定。
- 使用时按用户反馈记录结果，不预设成功，也不预设失败。
- 不用它规避上限计数——混合文本仍按同一口径计入总字符数。

## 7. 换语言等于换预算

- 换语言后重新计数、重新校验，之前该提示词的测试结论不自动继承。
- 中英两版是两条独立记录，各自标注证据状态。
- 用户只认可了中文版时，不因「意思一样」就认为英文版已通过。

## 8. 校验流程

1. 确定本轮沟通语言，确定目标平台与其字符上限。
2. 写提示词并保存为独立提示词记录，填入语言、预算、实际字符数与计数口径。
3. 运行 `python3 scripts/prompt_budget.py <文件> --budget <上限> --strict`。
4. 超限则按第 4 节顺序压缩后重跑，直到通过。
5. 用 `--markdown` 模式检查文档中的完整提交稿代码块，而不是把整份文档当一条提示词计数。

脚本只做字符统计与粗粒度占位符检查，不判定身份一致、语义正确或图片质量。
