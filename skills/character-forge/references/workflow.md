# 阶段、路由与迭代

## 1. 输入路由

| 请求 | 起点 | 不应做什么 |
|---|---|---|
| 给图提取人物、补全 | S0 识别已有信息，再 S1 | 将不可见细节称为精确复刻 |
| 纯文字设计角色 | S0 定义少量锚点，再 S1 | 虚构参考图依据 |
| 有认可全身图，要继续 | 恢复状态，检查是否需要 S2 或 S3 | 默认从头重做 |
| 已有角色改真人、水彩等风格 | 建新分支，复用设计，重做必要定妆 | 继承旧媒介笔触或已测结论 |
| 某个地方不对 | 回到该问题所在阶段 | 推翻所有认可项 |
| 用户拿自己的照片来演 | 切到模式 B，重新指定身份来源 | 套用固定角色的脸与体型 |
| 总结或出文档 | S5 检查资产与证据 | 将整理版冒充测试原文 |

## 2. 阶段必选／可选关系

| 阶段 | 默认地位 | 说明 |
|---|---|---|
| S0 任务与边界 | 必做 | 每次任务的起点 |
| S1 全身正面定妆 | **必做** | 正式交付的保底项之一 |
| S2 身份细化（头肩／半身） | 可选 | 脸不清楚时才展开 |
| S3 同图设定板 | **必做，最核心** | 正式交付的保底项之二 |
| S4 跨场景 | 可选 | 用户需要实际使用场景时才展开 |
| S5 资产化 | 必做 | 输出自包含 Markdown |

主线是 S0 → S1 → S3 → S5。S2 与 S4 挂在主线上按需进入，不为流程完整机械追加。

**复用优先。** 已有满足要求且获用户认可的资产可以直接复用，不必重新生成。已经认可过的全身基准不重做；已经认可过的同图设定板不重做；只有当角色设定发生实质变化、或用户明确要求重做时，才回到对应阶段并记录原因。

**辅助分图不升级为整合板。** 独立头肩图、独立侧面图、独立背面图、复杂配件局部验证完成后，核心设定板仍标记未完成。下一轮仍需生成或复用用户认可的同图设定板。只有在同图设定板本身已获认可时，S3 才算完成。

## 3. 阶段细则

### S0 任务与边界

输入：图片、原提示词、用户目标、已有项目资料，均可部分提供。
输出：本轮目标、身份模式（固定角色／用户扮演）、媒介、参考职责、可见事实与需要补全的内容。
检查：是否固定角色开发而非用户扮演；是否确需世界观事实核验；是否已有可复用风格模块。
不为创作任务搜集无关背景；涉及具体原作事实、平台限制或授权判断时，按宿主能力核验，不凭角色外观推断。

### S1 全身正面定妆（必做）

解决整体剪影、体态、服装层次、配色、鞋履及缺失部分。

- 单角色、单视图、正面、完整全身。按角色形态定义完整边界，不给动物强加人类鞋履要求。
- 简背景、清晰轮廓、自然站姿是默认预设，不是永久角色身份。
- 原图不可见的腿部、鞋履或其他结构属于设计补全，写明补全依据，不称精确还原。
- 原图有海报文字、对白、持物或背景时不自动带入定妆；用户明确需要时例外，并标为该次例外而非常态。
- 认可后记录全身基准。已满足要求且获认可的基准直接复用。

若仅提示词获认可而无实际出图反馈，记「方案认可，执行待测」，不要擅自升级证据。

### S2 身份细化（可选，按需）

用认可全身图或已确认脸部图制作半身／头肩图。只改取景与必要光位，不重选人物，不加新妆或新装饰。决定身份基准优先级。无须细化时记录跳过理由。

若已存在获认可的同图设定板，其左侧半身通常已经承担了身份细化职责，此时 S2 可直接记为「由 S3 设定板左侧半身覆盖」。

### S3 同图设定板（必做，最核心）

默认输出同一张图中的四个描绘：

1. **左侧**：放大的正面半身像，默认完整展示头部与双肩，上身自然裁至腰部附近。
2. **右侧从左到右**：标准正面、标准右侧面、标准背面三个全身。
3. 三个全身等比例，顶端与脚底分别对齐，完整入画，不重叠。
4. 左侧半身单独放大，不得为了对齐全身而缩小头部。
5. 四个描绘是同一个角色，不是四位人物。
6. 视角正确：侧面不为了展示双眼而转脸；背面不回头露五官。
7. 配件跟随人物解剖侧，不固定在画面同一边。
8. 所有视图延续同一套衣服与已确认补全结构，允许自然遮挡。

布局与数量必须明确；精确比例不是交付硬门槛。推荐横向画幅，3:2、左右约 35%／65% 可作初始预设，但按实际角色、发型、体宽和模型调整，不作为普遍规律。

输入默认使用已认可的全身正面基准。若已有更适合的身份图，明确其职责与未展示部位的文字来源；不默认要求多图融合。

背面设计用保守延续原则：复用已有结构，不无端增加徽章、口袋、尾饰或机械零件。用户希望大胆设计时可提案，但需要确认。

**失败与回退。** 出现单一视角问题（只有三个全身、缺左侧半身、侧面朝向错误等），先单独修该视角，再回到整合板。修正后仍需产出同图四描绘的完整版本并获用户认可。不得因为分图成功就把核心设定板标记完成，也不得把三全身版本当成核心板宣布完成。

### S4 跨场景（可选）

选与角色气质相符、能检查身份延续的一个简单动作。一个主要道具或无道具、两三项背景、一个明确目光目标。测试脸与体态、服装、动作接触、表情和媒介统一。
通过后不自动声称所有场景稳定；用户不需要时可跳过并注明。跨场景不作为正式交付的硬门槛。

### S5 资产化（必做）

先核对已确认、待定与未测试的内容，再整理双模式入口和记录。已测试原文保留独立条目；模块重写为新版本，需复测标签。
命名可以在此阶段完成，也可提前；名字不充当模型身份锁定手段。默认不写长篇未核验背景故事。

**这一步产出的是当前态资产。** 交付文档只写「现在是什么」：识别锚点表、固定前缀、两项基准图的
场景段、槽位表、已知限制。版本历史、证据台账、案例经验留在开发侧记录里，不进交付。
输出为一份自包含 Markdown，详见 [角色资产文档模板](../templates/character-document.md)；
交付前跑 `scripts/check_delivery.py`。

## 4. 固定锚点与变化范围

固定锚点从当前角色提取，不使用通用的固定长相清单：身份与年龄感、脸或头部轮廓、比例、发型或毛色、标志性细节、默认服装层次等。

默认**不进入**永久身份前缀的内容：永远张嘴笑、永远看镜头、脚尖外八、固定站姿、固定手持杯、固定灰底、固定镜头。用户明确指定为永久设计的内容例外，并标明来源。对任意场景不合理的默认姿态，优先作为场景预设而非身份。

变化范围由场景决定：表情、动作、镜头、光位、背景和道具。换装作为显式分支，不能偷偷改掉默认衣服。

## 5. 局部修正过程

1. 摘要本轮偏差，区分用户反馈、可见事实与推测原因。
2. 列明必须保持的已认可项。
3. 给出一项或一组关联改动。
4. 输出可复制完整修正版，而不仅给补丁。
5. 记录父版本和变化；失败版本保留结果与结论，不用失败猜测污染主基线。

## 6. 讨论与执行切换

「先讨论」保持在方案层。用户认可方案并明确继续落地时，生成所约定的交付物，不无休止重复确认。
普通「继续」只授权当前协作流程中下一轮内容，不授权付款、外部发帖、覆盖远端文件或调用收费生图。

## 7. 交付门槛

**正式交付门槛（默认）**

- 全身正面基准已实际生成并获用户认可，或已有等效认可资产。
- 同图半身＋正侧背全身设定板已实际生成并获用户认可。
- 关键设定及补全结构明确。
- 两项基准图的场景段可在交付文档内直接取得。
- 未解决项、未测试模式和缺失图片透明说明。

不要求：助手看过两张图、跨场景测试、独立头肩图、独立侧背图、批量验证，也不要求两种使用模式都实测。

**阶段草案**

用户明确要提前交付时生成「阶段草案」，列出缺项。草案不降低正式门槛的默认定义，只是提前交付并标注状态。不得因为能交草案就把「任意一项视角变化或场景变化」当作正式门槛。

**例外记录**

用户明确变更交付范围时记录该例外：谁在何时、以何种措辞改变了范围，以及因此跳过哪一项。

## 8. 反馈解释

只有同时满足以下条件，才把「不错」「OK，继续」默认解释为已实际执行并认可本轮结果：

1. 当前是用户实际生成图片、助手逐轮提供提示词的测试流程。
2. 上一轮给出的是可执行的生成提示词。
3. 用户没有说尚未生成、只是方案不错或仅在讨论。

讨论 Skill、讨论方案、选择服装提案、确认交付时，不套用该默认值。判定表与证据字段见 [验收与证据](quality-checks.md)。
