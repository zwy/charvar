# 待完善清单（动作库链路）

动作库出图链路（存储 → 描述 → 拼装 → 出图 → 锚定）已闭环，本文件只记**还没做**的需求：
做成一条删一条（含总览表的行），随时可以从「入口」直接捡起，不用重新考古。

- **优先级**：P0 = 直接影响当前出图质量、随时可开工；P1 = 明确承诺过的功能补全；P2 = 按需触发 / 打磨。
- **规模**：S（半小时内）/ M（半天内）/ L（一天以上）。

## A1（P0/M）：上半身 ai_draft 弱定位句扫描与改稿

- **现状与证据**：上半身 1 人共 80 条，79 条正面描述是 LLM 起稿（source=ai_draft）。
  「手举到左脸侧」这类只有方向、没有高度的写法，在 headshot 锚定下会把手位带到
  肩部（upper80v2_P005 实测：同种子只改文本可复现；写成「手掌贴在左脸颊、
  指尖齐眉、与头同高」后 seed 7/42 两张都贴脸成稿）。
- **做法**：一次性脚本扫上半身正面描述的「手/指/掌 + 举/放/贴」句，标出
  缺高度锚（同高/脸颊/眉/贴在…/齐…）与缺贴靠对象的可疑条目 → 对照
  `data/poses/pose-db-01/thumbs/` 缩略图逐条改稿。改法照 P005 定稿模式：
  **手势给高度锚 + 删取景外事实**（视角级写法模式见 docs/姿势库.md）。
- **入口**：读 `charvar pose action <pose_id>`；写 `--set '...'`；
  可疑清单直接查库：`pose_actions`（source='ai_draft'）× `pose_images`（line='上半身1人'）。
- **验收**：抽 3–5 条改稿，`charvar pose prompt <id> --subject <主体> --run`，
  手位与缩略图一致。

## B1（P1/M）：背景/光照句参数化

- **现状**：三种库线的背景句写死「背景简洁，突出角色。」（`charvar/pose_prompt.py` 的 `_SEGMENTS`）。
- **做法**：接 `presets/wildcards` 的 backgrounds / lighting 池（用户 demo 里的既定方向）；
  随机**必须走 `charvar.wildcard.seed_for`**（红线）；池子形态（通配符文件 or 列表）先定；
  CLI 给 `--background` / `--lighting` 之类的口子，网页在 B3 里同步。
- **验收**：同种子同动作，背景选项在池内命中且可复现；不加参数时行为与现在一致。

## B2（P1/M–L）：动作库页面编辑 UI

- **现状**：整页/弹层只读（描述展示 + 复制 + 角标）；读写接口都有了
  （`GET/PUT /poses/{pose_id}/action`），就差前端。
- **做法**：详情栏「动作描述」块加编辑入口 → textarea + 保存（PUT）+
  **AI 起草**按钮（后端包一个 describe 端点，复用 `charvar/pose_describe.py` 的
  `describe_one`）+ **从其他视角复制**；视角切换联动描述块（现在已联动，编辑态要跟随）。
- **入口**：`web/static/posegallery.js`（共用渲染层）、`web/static/posepage.js`、`charvar/api.py`。
- **验收**：网页改稿后 `charvar pose action <id>` 读得到同文本；AI 起草落库记 ai_draft 并可覆盖。

## B3（P1/M）：网页端生成接入（动作描述 → 提示词）

- **现状**：前端「从动作库加入」只挂参考图；动作描述尚未进入生成链路。
- **做法**：预设页 / Playground 选 pose 参考图时，按所选视角把 action_text 带出当动作草稿；
  拼装继续走 `charvar/pose_prompt.py`（`build_prompt`）语义，别在前端另造一条拼装；
  双人线 + 双主体参考图的选择（甲/乙 ↔ image1/image2 映射）顺带设计。
- **入口**：`web/static/genrefs.js`、`app.js`、`adhoc.js`；后端 `/generate` 的 references 结构已有 role 字段。
- **验收**：网页选「动作 + 视角」生成的图与 CLI `pose prompt` 同源同结构；不选动作时行为不变。

## B4（P1/M）：服装库网页接入（「从服装库加入」弹层 + 换装参数）

- **现状**：CLI 两条换装工作流已接（① `pose prompt --costume`：主体+动作+服装，
  <image1>/<image2>/<image3>；② `charvar costume prompt`：主体+服装站姿版），
  网页侧没有服装入口。
- **做法**：预设页/Playground 参考图区加「从服装库加入」（复用 costumegallery.js，
  role=`costume` 参考图来源）；服装参数（选中服装 id）接到与 CLI 同源的拼装段
  （build_prompt 的 costume 层，别另造文案）；双人 + 服装仍二期。
- **入口**：`web/static/costumegallery.js`、`genrefs.js`/`app.js`、`charvar/api.py`
  （参考图来源要新增 costume 类，服务端定路径）；docs/服装库.md「生图流程接入」已记 CLI 侧验收。
- **验收**：网页选「主体 + 动作（可选）+ 服装」出的图与 CLI 同源同结构。

## C 类（P2，按需触发）

- **C1 其余 4 个视角的描述**：俯/侧/斜/仰用到哪个动作补哪个。批量
  `charvar pose describe --angle <视角>`；单条 `--set`；写法先读 docs/姿势库.md 的
  15 条实测范式（先看该视角缩略图，别从正面文本机械改写）。
- **C2 pair60_P001 贴合细节**：描述写「脚掌伸向乙、抵住乙的膝部」但成图脚垂在乙腿侧——
  照 P005 方法改硬贴靠锚（「贴住/压在乙的膝上」）后固定种子重验。
- **C3 full_single_P008**：ai_draft 写「双膝向两侧打开」，线稿实际偏并拢——无伤大雅，顺路修。
- **C4 FEWSHOT 样板升级**：`charvar/pose_describe.py` 的 FEWSHOT 半身样板换成带高度锚的
  实测定稿（如 P005 的「指尖齐眉」稿），让未来批量起稿直接学对；改完 `--dry-run` 抽查起稿。
- **C5 AGENTS.md 补 pose 命令行**：姿势库段没提 `pose prompt` / `pose describe`；
  预算几乎顶格（36,855/36,864，`tests/test_docs.py` 会拦），加一行要等长削别行。
- **C6 同动作多视角叠加参考图（二期）**：同一动作发多张视角线稿一起锚姿势；
  动工前先试一例（两张视角 + 只写正面描述）看模型是否互相干扰——docs/姿势库.md「暂不接」清单已记案。
- **C7 上半身锚定对比实验**：headshot 单图 vs headshot+front 双图。文本修正后单图已稳（P005），
  双图对更复杂的手臂动作可能更稳；要验时临时改 `poses.subject_slot_for_prompt`
  让 upper 再多带一张 front，固定种子 A/B 对比即可。
- **C9 动作×服装廓形相容性**：张腿坐姿（full_single_P001）把 WIN-0001 鱼尾长裙
  稳定读成阔腿裤（同主体同种子、加关键词注记也压不住，两个种子复现）——模型对
  「裙装做不了这个坐姿」按动作结构优先改制；同理手被占住的姿势（双臂收在胸前）
  没地方放包。注记文本对部件完整性有效（外套回归），对部件**改型**无效；候选：
  pose 级相容性预判（按姿势给「下装画长裙，裙摆罩住
  双腿」的正向兜底句，别用否定式——显性召唤物反噬）、或出图后按关键词核对部件
  类型不匹配时标记。头上配件（贝雷帽）已由配件锚层解决（见已闭环）。
