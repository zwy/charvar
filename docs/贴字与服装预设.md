# 服装预设与贴字

`charvar/outfit.py` 与 `charvar/overlay.py` 的字段参考。**只写当前有效定义**——历史在 git log 里。
工作约定与红线见仓库根的 `AGENTS.md`。

两者都是出图后的组合能力，服务于「视频配方」的合成流水线（出图批 → 贴字 → 本地合成 reel）。

## 服装预设

`presets/outfits/*.yaml`。每条 = 英文服装描述段 `text` + 中文 `label`（贴字/展示用）+
可选 `caption_tags`（id → 英文 caption token，缺省 = id）。

子目录家族，**不进主预设下拉**（`list_presets` 只扫 `presets/actions/`）。

## 跨预设笛卡尔积

出图请求带 `outfit_preset`（+ `outfit_order`）：

| `outfit_order` | 变体顺序 |
|---|---|
| `outfit_first`（缺省） | 每件服装连播全部动作 |
| `pose_first` | 每个动作连播全部服装 |

- 变体 id = `{outfit_id}__{pose_id}`（`pose_first` 时反序）。
- caption 在 pose 之后插 outfit token。
- meta 带 `outfit` / `outfit_label`。
- 语义：`POST /generate`（带 outfit_preset）= `charvar gen --outfit … --outfit-order …`；
  网页生成页「服装预设 + 组合顺序」同源。变体顺序就是后续 reel 合成的播放顺序。

## 发型预设

`presets/hairstyles/*.yaml`（`charvar/hairstyle.py`），结构与服装预设同构：
`type: hairstyle` + `items: [{id, label, text}]`（`text` = 英文发型描述段，
`label` = 中文展示名）+ 可选 `caption_tags`（id → 英文 caption token，缺省 = id）。
独立家族，**不进主预设下拉**。

- **条目只写头发结构，不写发色**：长度 / 刘海 / 分缝 / 层次 / 卷度归发型 `text`；
  发色继承主体档案（identity_lock）或人物参考图。条目里写染发颜色会跟档案锁打架。
- **层级固定 动作→发型→服装**：发型层先并（`hairstyle.combine`，无服装时
  变体 id = `{发型}__{动作}`），服装层后并（`outfit.combine` 把发型层产物当输入，
  三层 id = `{服装}__{发型}__{动作}`，text = 动作+发型+服装）。发型**没有**单独的
  顺序开关——要调 reel 播放顺序用现有 `outfit_order`。
- **发型段同服装稀释红线**：追加在动作段之后，每条 ≤200 字符。
- **LLM 模式优先**：发型段走意图独立字段 `hairstyle`（逐字英文，zh 分支单开例外；
  服装+发型同给时例外合并）；锚定句按 `llm_prompts.reference_clause_table` 换发型版
  分句表——headshot/side/behind 分句不再让参考图提供头发结构，**发色/脸仍由参考图
  提供**；程序兜底（`hairstyle.descriptor_covered` + `insert_descriptor_sentence`，
  复用 outfit 的关键词覆盖实现）**先于服装兜底**执行，两段都缺时插入顺序才能落成
  动作→发型→服装。没有发型组合时系统提示词逐字不变（快照回归测试）。
- **发型锁冲突走约定**（classic 无法程序消除）：identity_lock 里发型只写发色、
  不写结构；含发型结构的主体做发型批时优先 LLM 模式（系统规则会把档案/参考图的
  原发型结构描述替换成 hairstyle 字段、只保发色），或先改档案把结构句挪出锁。
  classic 撞锁不做程序检测/特判。
- caption：发型 token 在 pose 之后、outfit 之前（`caption_tags.hairstyle`）。
- 入口：`POST /generate` 带 `hairstyle_preset`、`GET /hairstyle-presets`、
  `charvar gen --hairstyle`、网页②「发型预设」下拉、配方 `presets: [动作, 服装, 发型]`。

## 试衣用单动作预设

`presets/actions/outfit_*.yaml`：**每个预设只有 1 条变体**。服装 N 件 × 1 条 = N 张图
（动作预设一多就是 N×M 张，试装时先看一件衣服没必要全跑）。

| 预设 | 景别 / 角度 | 看什么 |
|---|---|---|
| `outfit_front_full` | full / front | 整体版型、裙长、鞋（唯一看得到丝袜/鞋/裙摆的档） |
| `outfit_three_quarter_full` | full / l45 | 立体版型与垂坠（lookbook 最经典角度） |
| `outfit_side_full` | full / l90 | 侧面厚度、鞋跟、裙摆侧形 |
| `outfit_back_full` | full / back | 背面、开背、拉链、鞋后跟 |
| `outfit_front_chest` | chest / front | 领口、肩线、袖型（上装细节） |
| `outfit_front_head` | head / front | 发型、妆造、耳饰（肩线以上） |

两条要注意的：

- **近景档（chest/head）会主动排除下半身**：`composer.closeup_framing_guard` 追加
  "no lower body, hips, waist, … shoes, legs"，ComfyUI 通路还自动注入同一套下半身负向。
  验上衣用近景档，验丝袜/鞋/裙摆必须用 full 档。
- **背景与光照已内置固定**：这 6 个预设指向 `wildcards/backgrounds_lookbook_v1.yaml` 与
  `wildcards/lighting_lookbook_v1.yaml`，**各只有 1 条** → 每张图背景光都一样，
  横向只比衣服。要换风格改这两个池文件里的那一行；**别往池里加第二条**——
  背景/光照是按变体 id（`{outfit_id}__{pose_id}`）取值的，多于一条就变成每件衣服
  配一个背景/一种光，对比失效。
  另外：取消「随机背景 / 随机光照」且没填「固定背景 / 固定光照」时，
  提示词里整句背景或光照会被省掉（`composer._render_suffix`：缺哪句省哪句），
  模型会自己发挥——要么留着随机开关，要么在固定框里写死。

## 贴字

`presets/overlays/*.yaml`。PIL 确定性后处理，**不改原图**。

产物落 `<data>/generated/<run_id>/labeled/{index:06d}.png`（scene 白名单含 labeled）。

| 字段 | 说明 |
|---|---|
| `position` | `left_top` / `right_top` / `left_bottom` / `right_bottom` / `center` |
| `margin_x` / `margin_y` | 画面宽 / 高的占比边距 |
| `font` | 字体名或路径；`""` = 自动 |
| `size` | 字号（短边占比） |
| `color` | 文字色 |
| `stroke` / `stroke_color` | 描边宽（短边占比）/ 描边色 |
| `plate` | `pill` = 圆角底板 |
| `plate_color` / `plate_padding` | 底板色（半透明）/ 内边距 |
| `opacity` | 整层透明度 |
| `rotate` | 整块文字旋转角（绕自身中心，不裁画面） |
| `max_width` | 换行阈值（画面宽占比；CJK 按字、拉丁按词归行） |
| `align` | 对齐 |
| `line_gap` | 行距 |

**文本来源** `text_from` = `outfit_label` / `pose_tag` / `variant_id` / `fixed`。

语义：`POST /runs/{id}/overlay` = `charvar overlay <run_id> --overlay <preset> [--text-from …] [--items 0,1]`。

## 字体解析顺序

1. `presets/overlays/fonts/` 里的文件
2. 系统候选：macOS PingFang / Hiragino、Linux Noto CJK、Windows 雅黑

`font: ""` = 自动。要跨机稳定就把字体文件放进 `fonts/`，
**只放可再分发的开源字体（OFL 系安全）；花字/美术字体的版权要单独确认**。
