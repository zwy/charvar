# 图片页库组合

图片页（`charvar/adhoc.py`）上的**固定构成拼装**工作流：前端 `web/static/adhocflow.js` +
后端 `charvar/adhoc_compose.py`（编排层）+ `POST /adhoc/compose`（`charvar/api.py`）。
**只写当前有效定义**——历史在 git log 里。工作约定与红线见仓库根的 `AGENTS.md`。

## 五种生图模式

图片页顶部的模式分段：**自由生图 / 单主体动作 / 双主体动作 / 人脸动作 / 换装**。

- **自由生图** = 不拼装：参考图平铺，锚定句手写，提示词就是用户给的。
- 其余四种 = 固定槽位 → `POST /adhoc/compose` 拼装（workflow=`pose` 的单主体/双主体/人脸
  与 workflow=`costume` 的纯换装）。**文案来自 `pose_prompt.build_prompt` /
  `build_costume_prompt` —— 与 CLI `charvar pose prompt` / `charvar costume prompt`
  同源同结构**（待完善清单 B3/B4 红线：拼装不另造一条锚定句）。

槽位状态分模式独立保存（切模式来回不丢）；构成变化自动重新拼装；提示词可手改——
手改后构成再变不自动覆盖，改用「重新拼装」按钮。

## 前端槽位（adhocflow.js）

| 模式 | 槽位 |
|---|---|
| 单主体动作 | subject（{id, kind} 二元组）+ pose + 可选 costume |
| 双主体动作 | subject1 + subject2 + pose（只认 `2人絡み` 双人库；不带服饰/人脸） |
| 人脸动作 | face（人脸库身份锚）+ bodyLock（手给体形锚）+ pose + 可选 costume |
| 换装 | 身份锚 = 主体档案或人脸二选一 + costume |

主体身份锚的 `kind` = 两步弹层里选的槽位图（六槽位之一，缺省回退 `front`）。

## 后端约束（与 CLI 完全对齐）

- face 与主体档案**互斥**；人脸流程不支持双人。
- 双人只认 `2人絡み` 动作库；双人**不带服饰/人脸**。
- 体形锚（`body_lock`）只在人脸流程手给。
- 换装条目必须有图；条目引用必须写全 `source/item`（跨库 id 重叠）。
- 动作出图（pose 工作流）没写动作描述时 400（`ComposeError`），不静默拼空句。

## references 与出图

`POST /adhoc/compose` 返回拼好的提示词 + `ReferenceSpec` 序列——**顺序即提示词里的
`<image1>`…**，出图时原样发 `/adhoc/generate`（服务端按 id 取文件，浏览器永远不给路径）。
参考图来源上限与自由生图一致（同一套三来源：上传暂存 / 主体档案槽位 / 最近生成原图）。

主体槽位 kind 缺省 = 按动作线型自动（半身 headshot / 其余 front，与 CLI 对齐）；乙槽恒 front。

## 改动同步

参数名或拼装结构变化时，CLI（`charvar pose prompt` / `charvar costume prompt`）、
网页（`adhocflow.js`）、`adhoc_compose.py` 模板层三处语义要一致；文案源头只有
`pose_prompt.py` / `pose_prompt` 侧的分段常量一处，别在编排层另写措辞。
