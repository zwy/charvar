## 写作规范（沿用 docs/姿势库.md「动作描述怎么写」）

- 80–160 字一段中文；**身体事实**（四肢/躯干/头怎么摆、重心与承重腿）+
  **机位事实**（朝向句「面朝画面左方」、俯/仰机位、近端遮挡与透视大小）。
- 手势/局部位置给**高度锚**（「指尖齐眉、与头同高」这类）。
- 取景外的事实别写（上半身动作不写腿）；不写身份/服装/表情/画风。
- **深度图专用补充**：深度图白=近、黑=远。描述里遮挡关系要按图核对真
  前后（「近端的手臂」「被躯干挡住」）——从正面文本机械改写是最大坑，
  动笔前必须看该视角深度缩略图。
- 双人强制「甲（位置说明）」「乙（位置说明）」指称，不写死 imageN。
- 写入：`~/.local/bin/charvar pose action <pose_id> --angle <视角> --set '<描述>'
  --source pose-db-02`；读：去掉 `--set`。

## 每条目的执行回路（已调优，照抄勿改）

1. **读深度缩略图**：`data/poses/pose-db-02/thumbs/<pose_id>_<front|high|
   side|diag|low>.jpg`（JPEG 300×400，别读 `img/` 原图，浪费上下文）。
   视角映射：正面=front、上から=high、斜め=diag、横=side、下から=low。
2. **写/复制文本**（入库 `source=manual`）。
3. **出图验证**（1 张，固定 seed 0）：
   - 单人全身：`~/.local/bin/charvar pose prompt <pose_id> --angle <视角>
     --source pose-db-02 --subject karina_b --run --json`
   - 上半身（upper80v2_*）：同上（CLI 自动取 headshot 槽位）。
   - 双人（pair60_*）：`--subject karina_a --subject2 karina_b`
   - `--json` 输出含生成图路径与缩略图路径；**只读缩略图**省上下文。
4. **目检三样对比**：深度缩略图 ↔ 生成图缩略图 ↔ 描述文本。判定是**姿势
   与遮挡关系吻合**（人数、朝向、四肢摆位、前后远近），不是画风像人偶。
5. **不吻合处置**：
   - 先换种子重跑一次（`--seed 42`）——单只多余腿/手这类多为 seed 偶发
     （见 memory 跪蹲案例），不是文本错。
   - 仍不吻合 → 文本有问题：修正描述（重点查：朝向句、近端远端写反、
     高度锚缺失），重新入库并**重出图复核**。
6. **文本修正过的条目，同步回写线稿库同视角**（`--source pose-db-01`），
   保持两库一致；未修正的不碰线稿（正面线稿侧多为 ai_draft 原稿）。

## 批量与子 Agent 组织

- 主会话保留全局状态（本档 + 数据库），**验证工作交给子 Agent**，
  每批 ~15 条：Agent 会话只装「本档 + 本批 pose 列表 + 一段批内约定」，
  不带全对话；子 Agent 用 general-purpose，串行出图（一次一条命令）。
- 子 Agent 返回：每条 one-line 结论（ok-fixed / ok-unchanged / text-retried-ok /
  BLOCKED：<原因>），不要贴全文。
- 并发 ≤ 2 个子 Agent（ComfyUI 队列与本地网开销）。
- 分批顺序：正面先全量（先全身两系、上半身、双人最后）；其余四视角按
  上から→斜め→横→下から、同视角内按分线推进。
- **重复出错要回填本节**：每次子 Agent 报 BLOCKED 或主会话发现踩坑，
  在「坑记录」补一条，让下一批的 brief 引用。
