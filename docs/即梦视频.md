# 即梦视频通路

> 状态：2026-11-04 集成落地。上游 = 本机官方 `dreamina` CLI（v1.4.21 实测），
> charvar 侧 = `charvar/dreamina_video.py` + `adhoc_video` 的 dreamina 分支。

## 事实表（CLI 1.4.21 `-h` 实测，CLI 升级后要同步）

CLI 位置 `~/.local/bin/dreamina`（解析链：`DREAMINA_CLI` env >
PATH > `~/.local/bin/dreamina`，同生图）。**没有 API key 可配**：鉴权 = 本机
`dreamina login` 的登录态（`~/.dreamina_cli/`；`dreamina user_credit` 能返回积分即就绪）。

### 子命令与 charvar 输入映射

| charvar 输入 | 即梦子命令 | 说明 |
|---|---|---|
| 只给提示词 | `text2video` | ratio 缺省 = 即梦默认 16:9（charvar 显式发） |
| 首帧单图 | `image2video` | 缺省 `--ratio` **从首帧图推断**（推荐）；显式发给时 2.0 系可独立设 |
| 参考图（≤4）/ 参考视频（≤2） | `multimodal2video` | 全能参考（原 ref2video）：图≤9、视频≤3、合计≤12，**至少一条图或视频**；单条音视频时长须 2–15s |
| 首帧+尾帧 | ✗ 未接入 | 上游有 `frames2video`；charvar 没有尾帧入口，请求带了提交前报错 |
| 多图故事 | ✗ 未接入 | `multiframe2video`（2–20 图、模型固定不可选） |

首帧与参考图/参考视频**同给**会被提交前拦下（即梦图生视频只收 1 张首帧）——
这与 OpenRouter 的「frame_images 优先、原样放行」不同：即梦侧没有可承载组合的
子命令，宁拦不多发。

### model_version 档位表

| model_version | 分辨率 | 时长 | 子命令面 |
|---|---|---|---|
| seedance2.0 / 2.0fast / 2.0mini / **2.0fast_vip（默认）** | 720p 恒定 | 4–15s | text/image/frames/multimodal |
| seedance2.0_vip | 720p / 1080p / 4k | 4–15s | 同上 |
| seedance2.5 | 480p / 720p / 1080p | 4–30s | 同上，**VIP-only**（本机账号 standard 用不了） |
| seedance1.0fast（老） | 720p | 5–10s | 仅 image2video |
| seedance1.5pro（老） | 720p | 5–12s | image2video / frames2video |

- ratio **只有 6 档**：1:1 / 3:4 / 16:9 / 4:3 / 9:16 / 21:9 —— **没有生图侧的 2:3/3:2**。
- 每模型的三条 ratio 配对规则（CLI -h 明文，charvar 已拦）：**2.5 图生视频拒收任何
  显式 ratio**（输出跟首帧走，前端把画幅锁「自动」）；**legacy 模型（1.0fast/1.5pro）
  显式 ratio 必须与首帧一致**（charvar 按 PIL 读首帧尺寸 ±2% 预检）；2.0 系可独立设。
- **全能参考的输入媒体时长**：2.0 系单条/合计 2–15s、2.5 是 2–30s —— charvar 用
  ffprobe 预检参考视频时长（ffprobe 不在就跳过，交上游裁决）。
- `--video_resolution` 是**必填**参数（没有「不发」这个路径）；上游对
  duration / video_resolution / 显式 ratio **严格校验、拒收不静默调整**。
- 枚举表两处同源：`charvar/dreamina_video.py` `_VIDEO_MODELS`（校验）+
  `web/static/tables.js` `DREAMINA_VIDEO_MODELS`（下拉）——改一处要同步另一处，
  以 `dreamina <子命令> -h` 为准。
- CLI 各子命令自己的默认模型互不相同（text2video=2.0fast、其余=2.0_vip），
  charvar **每次显式传** `--model_version`，别依赖 CLI 默认。

## 与生图通路的共用与差异

- 直接复用 `dreamina_image` 的基础件：`resolve_binary` / `_run_cli`（鉴权标记
  判型）/ `parse_task_output`（从首个 `{`/`[` 行起抠 JSON；视频的进度行是
  `download video N URL:`）/ `query`（`query_result` 与子命令无关）/ 异常族
  （在 `dreamina_video` 按 `DreaminaVideoError` 别名引用同一基类族）。
- **无 seed**：请求值只记 manifest，绝不进命令行。
- **收片竞态与终态保护**：每路收片用**独立** download 目录（CLI 按确定性文件名下载，共享目录并发两次下载互相截断）；失败留痕走 `_mark_if_open`（写前重读盘上 manifest，另一路已收成 ready 就不覆写 —— 实测踩过 ready 被抹成 failed）；`refresh` 对缺 gen_status 的响应以 poll_error 暴露（不静默当中间态，否则轮询永不停）。
- **无逐条价目**：CLI 不给价、任务 JSON 只有 `commerce_info` 权益标签；
  `VideoResult.cost` 对即梦恒 None，前端成本预估区对即梦显示积分提示文字。
- **提示词长度上限无文档**（别抄生图的 1592/1992）：charvar 不做提交前长度拦截
  （只拦空串），上游报超长时 fail_reason 会透传；实测出上限后再补校准。
- **首用合规确认**：部分模型首次使用需先在即梦 Web 端用该模型完成一次生成，
  提交返回 `AigcComplianceConfirmationRequired` —— charvar 识别该话式并在报错里
  给网页端指引；重试救不回来，`dreamina login` 也解决不了。
- **产物 URL 会过期**：成片终态后立刻 `query_result --download_dir` 收片；
  产物路径读 stdout JSON 的 `result_json.videos[].path`（视频任务 `videos[]`，
  兜底 `images[]`；本地 `tasks.db` 里的 result_json **不含 path**，别倒查库）。
  落盘格式按魔数重新嗅探（不信 CLI 文件名后缀），转存 `original/000000.{ext}`，
  海报帧照旧 ffmpeg 抽。

## 异步作业与轮询

- web：`POST /videos/generate`（`backend: "dreamina"`）提交即返回 pending；
  manifest `job.id` = 即梦 `submit_id`；中间态 manifest 记 `in_progress`
  （即梦只有 `querying` 一个中间态，web 侧归一）；`refresh` 幂等，终态后不再
  打 CLI。轮询是**每次一发 query_result 子进程**（~1s 开销），8s 节奏可承受，
  但别在子进程里 `--poll` 长等待（会挂住 web 轮询线程）。
- CLI：`charvar video dreamina` 阻塞轮询（`--timeout` 默认 900s，作业超时仍在
  云端跑，manifest 保持 in_progress，网页可续查）。
- OpenRouter 侧的终态词表是 completed/failed/cancelled/expired；即梦是
  success/fail —— `adhoc_video.refresh` 按 backend 分流，别共用一个词表。
- 参考视频暂存池 `_vrefs/` 两供应商共用（48MB 上限是 OpenRouter base64 口径，
  即梦直传本地路径、上限不约束它，但暂存校验共用）；成片 ready 清池、失败保留
  以便重试 —— 与 OpenRouter 同策略。

## 配置

- 设置页「即梦视频（Seedance）」组：只有 model 一项（对齐 OpenRouter 视频组）；DB
  顶层键 `dreamina_video`（保存白名单里，改设置页代码时别漏）。
- env：`DREAMINA_VIDEO_MODEL`（默认链：请求显式 > 设置页 DB > env >
  seedance2.0fast_vip）、`DREAMINA_VIDEO_TIMEOUT`（默认 900s；CLI `--timeout` 与 web 作业等待都走它）。
- 「跟随设置默认」要真跟随：网页模型下拉空值就发空到后端，后端走 DB > env 链。
