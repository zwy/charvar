# 配方系统参考

`charvar/recipes.py` 的 YAML 字段与步类型参考。**只写当前有效的定义**——历史在 git log 里。

配方定义 = `presets/recipes/<slug>.yaml` + `<slug>.md` 成对。YAML 严格模式：未知根/步字段显式报错。
文档 `doc:` 相对 recipes/ 目录，读不到不阻塞执行。

配方大类由**末步**推导：

| 末步 | 大类 |
|---|---|
| `video_synth` | 合成配方（本地合成 MP4） |
| `video_model` | 生成配方（OpenRouter 视频模型直出） |

## 线性步骤

```
images → overlay → video_synth
   ↓        ↓         ↓
  贴字步   贴字      本地合成
```

- **`images`**：主体 + 预设（`presets: [动作, 服装, 发型]`，可叠可缺省）笛卡尔积建 run；
  层级固定 动作→发型→服装（发型层先并、服装层后并）。
  - `mode: llm` 走 LLM 改写（硬前提：主体模板 + 参考图槽位就绪；LLM 输出替代 master 拼接，预设文本只做改写输入）。
  - `push: comfyui` 自动提交 + 等待 + 同步成品，`reference_kinds` 注入 image1..N。
  - `run_id: <既有 run>` = 绑定不建批。
  - `fixed_background` / `fixed_lighting` 固定背景/光照，覆盖通配符池 —— 轮播类成片跨帧一致用；转面橱窗 `turnaround_showcase` 即此用法。
- **`overlay`**（贴字步）：`input` = 前面 images 步的 label，缺省取最近一个。
- **`video_synth`**：`presets/video` 预设合成本地 MP4。`use_labeled: true` 时同一来源 run 的贴字产物优先
  —— `render_video` 有可选 `images_dir`，缺省仍是 `original/`。

**消耗步统一 gate**：来源 run 成品没齐就停在 `waiting` 并写原因，不算失败。

## 检查点

`step.manual` 缺省：`images=False`、`overlay=True`、`video_synth=True`。

- 执行到 pending 的 manual 步停（`status=waiting`）。
- `--continue` / `POST /recipe-runs/{id}/continue` 批准当前 manual 步推进，之后的 manual 步再停。
- failed 步 continue 直接重试。
- **`--continue` 是「续跑已有运行」** —— 首次必须不带它（`charvar recipes run <名>` 建运行并停在首个检查点），
  否则报「没有可继续的运行」。

## 状态

`data/generated/recipe_runs/<recipe_id>/manifest.json`
（recipe_id 白名单 `^recipe_[A-Za-z0-9_.-]+$` 且无 `..`，同 adhoc 严格度）。

**不建 DB 表**、不落 runs 表。配方定义改版（步数不一致）时 continue 拒绝，要求重建。
删除一次运行 = `DELETE /recipe-runs/{id}`（网页「配方 → 配方运行」行内「删除」）：整目录清掉，
只清编排状态 —— 图/视频产物在 Playground / 历史 / 视频各页自理。列表按时间倒序，
时间格式与生成历史一致。

## 入口（三处语义一致）

| 入口 | 形式 |
|---|---|
| CLI | `charvar recipes list\|run\|status`（`--continue` 续最近一次；`run` 加 `--image-backend/--image-model/--image-resolution/--image-quality/--video-backend/--video-model/--video-resolution` = 运行级生成参数，首次 run 生效落 manifest） |
| API | `/recipes` `/recipes/{name}` `/recipes/{name}/run` `/recipe-runs*`（`DELETE /recipe-runs/{id}` 清运行记录，产物不碰） |
| 网页 | 顶栏「配方」页签（`web/static/recipes.js`：列表/详情/文档/开始运行/检查点继续/成片预览/运行删除） |

## 运行级生成参数（配方页「生成参数」面板）

生成参数（backend / model / 分辨率）**不进配方 YAML** —— 由运行级下发并锁进 manifest。

| 组 | 字段 | 取值 |
|---|---|---|
| `gen.image` | backend / model / resolution / quality | backend: comfyui/openrouter/dreamina；resolution 字面值按所选后端/模型枚举（comfyui 1k/2k） |
| `gen.video` | backend / model / resolution | backend: openrouter/dreamina（视频后端接入即梦：`adhoc_video` 按供应商分派，作业轮询双通） |

- **优先级**：运行级显式 > 步级显式 > 设置页/env 默认链（`_effective_image_params` /
  `_effective_video_params`）。时长/画幅/种子不进运行级（脚本与构图归配方管）。
- **生效范围**：只作用于 `adhoc_image` / `combo_image` / `video_model` 步；
  `images` 步 `push: comfyui` 与 `video_preset` 不受影响。
- **落盘与 continue**：`RecipeRunState.gen` 随 manifest JSON 落盘，continue 复用同一组；
  要换参数 = 重新开始一次运行。旧 manifest 无 `gen` 字段 = None，行为同旧版。
- **入口**：网页「生成参数」卡（`recipes_genparams.js`，localStorage 记忆）/
  CLI flags（上表）/ API `POST /recipes/{name}/run` body 的 `gen` 字段。

## 生成步

### `adhoc_image`（单图，Playground 通路 `charvar.adhoc`）

| 字段 | 说明 |
|---|---|
| `prompt` | 必填。原样使用；唯一模板机制 = `{{服装}}` 占位符（配 `dress_from`，见下行） |
| `dress_from` | 指向声明了 `costume` 过滤器的 pick 步：把选中服饰条目的 `prompt_text`（缺省回退 keywords）注入 prompt 的 `{{服装}}` 占位符；占位符与字段必须成对出现，选中条目记在 manifest 可复现 |
| `backend` | `comfyui` / `openrouter` / `dreamina`；缺省 = 运行级参数（无则 `openrouter`） |
| `model` / `aspect` / `resolution` / `quality` | 仅 openrouter |
| `negative_prompt` | 仅 comfyui |
| `seed` | 缺省用配方级种子 |
| `workflow` | 仅 comfyui |
| `reference_labels` | 参考图 = 引用配方 `refs:` |

产物落 `data/generated/adhoc/<id>/`，outputs 记 `image_run_id` + `/adhoc/<id>/image`。
**retry 幂等**：产物在就复用，不重复生成。

### `video_model`（OpenRouter 视频异步作业，`charvar.adhoc_video`）

| 字段 | 说明 |
|---|---|
| `prompt` | 必填；或 `prompt_from` 取 LLM 脚本步产出（二选一） |
| `prompt_from` | 前面 `video_script` 步的 label —— prompt 用其 outputs.script |
| `model` / `duration` / `resolution` / `aspect` | 不发送 = 留空 |
| `seed` | — |
| `frame_from` | 前面 images/adhoc_image/**combo_image**/overlay 步的 label |
| `frame_index` | 缺省 0 |
| `frame_ref` | 配方 refs 的静态图 |
| `frame_slot` | `first_frame` 缺省 / `last_frame` |
| `last_frame_from` (+`last_frame_index`) | 补尾帧 |
| `reference_labels` | refs → input_references 图 |
| `video_ref_labels` | video_refs → input_references 的 video_url（Seedance gen2+ 才接） |
| `video_from` | 前面 video_synth/video_model 步的成片 → video_url |

**异步语义**：提交（`adhoc_video.generate(wait=False)`，run_id 即刻进 outputs）→ 轮询
`adhoc_video.refresh` 直到 ready/failed 或超出 `wait_s`（缺省 300s）。

- 超时转 `waiting`，作业本身在 OpenRouter 继续，continue 续查**不重复提交**。
- 作业 failed → 步 failed；continue **清掉死作业重新提交**（重新计费，之前的失败原因在
  `outputs.previous_error…`，失败 manifest 留在 Playground 列表）。
- 提交被拒（枚举/key 错）= `PresetError` → failed，continue 前先修配置。

## 随机三库配方（pick / scene_design / combo_image / video_script，首帧先行与脚本先行两种顺序都合法）

面向**库**而不是某一条的随机配方；示例 = `presets/recipes/random_cast_video.yaml`（每跑一次换一批选角）。YAML 不写死任何条目。

### `pick`（随机选库，`charvar/casting.py`）

| 字段 | 说明 |
|---|---|
| `face:` | 人脸库过滤器 `{sources[], section, hair[]}` —— sources 必须是已登记库 |
| `pose:` | 动作库过滤器 `{sources[], lines[], categories[], angle, single, allow_text, pose_ids[]}` —— `angle` 缺省正面；`single` 缺省 true（排除 2人絡み 双人）；`allow_text` 缺省 false（只选有姿势参考图的动作），true 时**无图文本动作**（自建库 studio）也入池、但要求该视角描述已写好（组合首帧与脚本全锚在描述上），选中后文本条目 `thumb_url` 为空串；`pose_ids` = **精选白名单**（池子钉死到指定动作——单测某条/精选子池用，与 categories 叠加取交） |
| `costume:` | 服饰库过滤器 `{sources[], categories[], media}` —— media=real\|anime；**纯文本（无图）条目天然排除** |

- 至少声明 face/pose/costume 之一；过滤器键白名单 + sources 登记 + 枚举校验在**解析期**锁（错了不开跑）。
- 随机一律 `wildcard.rng_for(state.seed, f"{recipe_run_id}:pick:{label}:{目标}")` —— key 含 recipe_run_id：**每次运行换一批**，同一运行内 continue/重试固定同一批（pick 幂等：outputs 已有就复用）。
- **动作描述补齐 A→B**（选完动作立即做）：A = 另一注册库同 `(pose_id, angle)` 的描述**原文复制**写回当前库（`set_pose_action`，source 随双库原行）；B = `pose_describe.describe_one` LLM 看图起稿（落库 ai_draft；起稿措辞按库 display_type 分叉——深度库说「深度图 白=近」，缩略图也随库取）。两库都没有且 LLM 失败 → 步 failed，先配好 LLM（视觉）或手写再 continue。
- outputs：face/pose/costume 三块元数据 + thumb_url（`/faces|poses|costumes/image/…` 现成路由，浏览器不落路径）+ `action_origin`（existing / twin_copy(…→…) / ai_draft）。

### `scene_design`（LLM 场景设计，`charvar/scene_design.py`）

- `input:` 必填、指向前面的 pick 步；`hint:` 可选（给 LLM 的场景方向提示）；`model:` 覆盖 LLM。
- `script_from:` 可选指向**前面的 video_script 步**——脚本先行配方（`random_cat_skit_video`）按
  已定稿脚本设计场景：brief 追加【视频脚本（已定稿，首帧画面从这些拍点开始）】材料段 + 规则
  「脚本拍点涉及的舞台/道具/方位必须在场景里装得下」。只对 scene_design 生效（其他步解析期报错）。
- 输入 = 动作描述 + 动作名/分类 + 服饰要点（costume keywords）（+ 已定稿脚本）→ `llm.chat_json` 出 `{"scene": …}`；校验中文 30–150 字、不写人物外观/人数/姿势。
- outputs：`scene_text` —— 供 combo_image 与 video_script 引用。

### `combo_image`（三库组合出图步）

- `input:` 必填指向 pick 步；`scene_from:` 可选指向 scene_design 步；出图参数与 `adhoc_image` **同名同语义**（backend/model/aspect/resolution/quality/negative_prompt/workflow/seed）。
- `strip_accessories:`（缺省 false）+ `framing_extra:`（可选）—— 舞蹈首帧用的两个开关：前者把服饰图锚/要点注记/身材锚整个换成「只锚服装主件与鞋袜，包/帽/墨镜/手持物一律不带入画面」的剥离措辞（`pose_prompt` `_*_STRIP` 族，围巾/手套保留）；后者把一段框景文本拼在构图段之后（仅单人全身/半身生效）。
- `close_up:`（缺省 false）—— **特写首帧**（随机 MV 升级版即此用法）：提示词换 `pose_prompt.build_closeup_prompt`（面部大特写构图 + `scene_from` 场景照常替换背景句），**参考图只传人脸**、不进动作/服饰段（pick 无 pose 也能出首帧）；与 `strip_accessories`/`framing_extra` 同给解析期报错（语义不相干）。
- **文本动作首帧**：pick 选中 `display_type=text` 的动作（`allow_text: true`）时，`build_prompt` 走
  `pose_has_image=False` 的文本锚路径（mannequin 段整个去掉、lead 换「做出下面的动作」），**参考图
  只有人脸与服饰**、没有姿势图 —— 动作描述（studio 条目的起势文本）承担全部锚；`style_lock` 等其余注入点不变（荒诞动作配方 `random_absurd_video` 即此用法）。
- **猫主角首帧**（`subject_kind: cat`，`random_cat_video` 即此用法）：**无参考图** —— 步字段
  `action_anchor:`（`full` 缺省 / `setup`）—— `setup` 只锚动作描述的**起手+机位段**（首个
  「下一拍」之前），剧本尾段三拍归 `video_script` 步——整段进首帧时尾段的瘫/躺姿势会把
  额外的猫召唤进图片（实测地铁霸座两连翻车）；三只猫配方 v2 起都用 `setup`
  （`random_cat_skit_video`/`random_cat_naughty_video`/`random_cat_video`）。`appearances:`
  是**猫外观描述池**（品种/体型/毛色，不写性格），运行期以固定 key
  `{run_id}:appearance` 掷骰选一记进 outputs（retry 幂等复用）；提示词换
  `pose_prompt.build_cat_prompt`（外观段+猫动作文本锚+构图/场景/禁令，**没有任何 <imageN> 槽位**，
  ComfyUI 纯文生图）；与 `close_up`/`strip_accessories` 互斥、池空/空白条目解析期报错；
  `style_lock`/`safety_lock` 照常两头注入。解析期要求同配方 `video_script` 的
  `subject_kind: cat`（多镜/伴舞不接）：有 `frame_from` 时脚本措辞换猫版、**外观由首帧步
  outputs 继承**（brief 自动带【主角·外观】材料段）；无 `frame_from`（脚本先行，贱猫小品/
  捣乱/荒诞猫三配方即此）时**脚本步按同一固定 key 自掷外观**（解析期要求配方里存在带
  `appearances` 池的猫首帧步）——脚本与首帧同一只猫，靠掷骰 key 而非继承。
- `style_lock:`（缺省空）—— **全局质感锁**（combo_image 与 video_script 都吃）：条目串成一段「【全局质感（全程一致）】」——close_up 特写插在构图句与背景句之间、常规首帧拼在 `build_prompt` 之后、video_script 写进 brief 材料段；例：cinematic live-action / high-key bright lighting（两个 MV 配方已铆）。
- `safety_lock:`（缺省空）—— **安全红线锁**（机制同 `style_lock`，两头铆；仅 combo_image/video_script 两步）：串成「【安全红线（全程一致）】」注入首帧提示词尾部，video_script 一侧再加输出要求「逐条落进『避免出现』节」把安全写进成片提示词本体；条目空白与 **multishot 同给**在解析期显式报错（暂只支持单镜脚本，`random_absurd_video` 即此用法）。
- 提示词走 `pose_prompt.build_prompt`（face_section + costume + pose_display + **`background_text=`** —— scene 文本替换固定的「背景简洁，突出角色。」句）；**描述与服饰要点从 DB 现读**（手改即时生效）。
- 参考图序 = 人脸 → 动作 → 服饰（与 CLI `--face --costume` 同槽位序，服务取图走各自 prepared 缓存）；Playground 通路出图，**retry 幂等**（image_run_id 在且产物在就复用）。
- `frame_from` 的合法帧来源因此多一个 combo_image。

### `video_script`（LLM 视频脚本步，`charvar/video_script.py`）

- `input:` 必填指向 pick 步；`scene_from:` 可选；`duration:` 缺省 5（写进脚本的时长声明）；`types:` 可选类型池覆盖；`model:` 覆盖 LLM。
- **类型池** `DEFAULT_TYPES`（8 种运动族：跳舞/原地律动/慢速转身/连续摆拍/走向镜头/伸展/回眸/拨头发）用子种子抽取注入 brief（不让 LLM 自己随机）；brief 硬规则 = 单人、从首帧姿态接续、同装同景同光、一镜到底、分秒动作顺序、结尾留余韵、按起始姿态自适应（坐/卧类只做姿态可达的动态）。
- **默认文本模式不传图**（首帧是同一套描述链出的）；`frame_from:` 指向本步之前 images/adhoc_image/combo_image/overlay 步 = **看图模式**：真实首帧图随消息交给视觉 LLM（PIL 压长边 ≤1280），brief 换「以附图实际姿态接续」措辞 —— 帧步未完成 gate 等待（要求设置页 LLM 为视觉模型）。
- `amplitude:`（`normal` 缺省 / `large` / `skit` / `naughty`）—— large 换大幅版规则 6（跳跃/转体/甩头/大幅挥臂 + 起势→主段→收尾编排结构规则 7），normal 保持原 brief 字节；normal+无 frame_from 是旧配方行为。large 规则 5 允许蹲姿/俯身**蓄力姿态**直接发力衔接起跳/前冲/爬行/翻滚（荒诞动作起势即此），躺/卧/倚靠仍只做小幅连贯动态。`skit` = **拟人贱剧三拍档**（规则 5–7 换「起手充分→转折突然→贱兮兮收尾定格」剧本规则，表情戏贯穿；**只接猫**——配 `subject_kind: person` 解析期报错，措辞专配双足拟人小品，与 large 的四足大幅规则互斥）。`naughty` = **真猫捣乱三拍档**（规则 5–7 换「盯上→得手→装无辜」恶作剧规则：四足真猫身手、禁止拟人直立，装无辜表情反差即笑点；**只接猫**，同解析期报错）。
- `safety_lock:`（缺省空，同 combo_image 两端声明）—— brief 追加【安全红线（全程一致）】材料段 + 输出要求追加「把【安全红线】逐条写进『避免出现』一节」的规则；`multishot: true` 同给 = 解析期报错（暂只支持单镜脚本）。
- `subject_kind:`（`person` 缺省 / `cat`）—— 猫版措辞（「同一只猫」「不出现人类」、四肢与尾巴参与等；person 路径 brief 字节不变）；与 multishot/ensemble/close_up 互斥（解析期报错）。`cat` 的外观材料两种来源：带 `frame_from`（看图脚本）时从首帧步 outputs 继承；**不带 `frame_from`（脚本先行**，贱猫小品即此）时脚本步按**同一把固定 key** `{run_id}:appearance` 自掷——配方里须有带 `appearances` 池的猫首帧步（解析期校验），脚本与首帧恒同一只猫。
- `crowd:`（`solo` 缺省 / `backdrop`）—— **背景人物档**（combo_image 与 video_script 同给且必须一致，否则解析期报错；其他步设值报错）：solo = 现行为（猫版禁人类与第二动物）；backdrop = 公共舞台的市井合理性——允许**远景虚焦、与主角零互动**的场景人物进画面，首帧禁令句与脚本硬规则同步换成「远景、虚焦、零互动」措辞（`random_cat_skit_video` 即此用法；人群提示词来自池条目自带，场景步 hint 只作规则兜底）。
- **多镜模式 `multishot:`**（缺省 false；须显式 `duration:`）：编号镜头 + 每镜起始秒切点 + 镜头语言的分镜结构，正文后附【实录声场】【配乐】两段（支持音频生成的模型照此出声，不支持的作氛围描述读取）；`ensemble:` = 伴舞从第 2 镜入画（须配 multishot）；`shots:` 镜头数（2–6，缺省按 duration 推 ≥12→4 / ≥8→3 / 其余→2）。`random_mv_video` 即此用法。
- **多镜可选项**：`opening: face` = **特写开场**（第 1 镜保持面部大特写、第 2 镜起切全身编舞，伴舞顺延第 3 镜起入画）；`text_fx:` + `text_pool:` = **两处背景大字**（中段爆点 + 末镜亮相，词对从池子掷骰、记进 outputs.text_words 并逐词锁进脚本校验，默认池 HIT/OWN IT/SHINE/GO GO/LOVE）—— 均 `random_mv_video_up` 即此用法。
- 输出校验 400–3200 字中文且提到「首帧」（多镜模式另要求「镜头」）；outputs：`script / clip_type`。

### LLM 链与幂等

- 所有 LLM 环节：`step.model`（请求显式）> `settings_service.llm_overrides(conn)`（设置页 LLM 组）> env（`LLM_MODEL` 等）。
- 检查点建议（舞蹈/荒诞等**首帧先行**配方即此布局）：**选完库停一次**（看选角+场景文本）→
  **首帧+脚本停一次**（看图+脚本）→ 批准才提交视频。**脚本先行**配方（三猫/random_cast_video）
  反过来：选库+写稿自动，停在场景步前**脚本人工过目**。全部 manual 可在 YAML 改。

## 配方级素材声明

`refs:` 与 `video_refs:` 是配方级声明，步内按 `label` 引用（label 全局唯一）。

| 声明 | 形态 | 取值 |
|---|---|---|
| `refs:` | `{from: subject\|run\|asset\|pick, …}` | `subject` 必须配配方级 `subject:`（槽位图走 prepared_reference 缓存）；`run` 取 `original/{index:06d}.*`（`index: 0` 缺省）；`asset` = `presets/recipes/assets/<单文件名>`（禁路径穿越；图片后缀）；**`pick` = 随机选库产物的人脸条目图**（`step:` 必填指 pick 步 label，运行时取其 outputs.face → `faces.prepared_reference_file` 压缩图；选库未完 gate 等待）——舞蹈随机脸版（`dance_a_sway` v2）用它把「随机脸作 `<image1>`」接进固定提示词首帧步 |
| `video_refs:` | 同形但不允许 `subject`/`pick` | `asset` = 视频；`run` = **adhoc_video 作业**（`video_file()`，成片 original/ 下唯一文件） |

- 缺素材 / 作业未完 → `_GateStop`（waiting 可 continue）。
- 素材路径非法 → 解析期 400。

## 已知问题

- **`stockings_showcase.yaml` 第 2 步的 `presets` 引用了服饰家族名 `stockings_8`**，
  而 `presets:` 位按名解析的是**动作/服装/发型预设**（`presets/actions/`、
  服饰家族、发型三族笛卡尔积）。`stockings_8` 是自建服饰条目的 category
  （家族名，见 `presets/costumes/studio/`），不是动作预设 —— 该步在运行时会因
  「预设不存在」失败。改法：该步只挂动作预设，服饰家族另用配方级素材或服饰参数表达。
  结构校验（`tests/test_presets_structure.py::test_recipe_preset_refs_resolve`）
  已不再依赖运行时 DB，未灌库时也能通过。
