# 主体档案（subjects）

主体档案的存储结构、导入流程与双向同步规则。**只写当前有效定义**——历史在 git log 里。
工作约定与红线见仓库根的 `AGENTS.md`（它的「导入主体档案」节给的是主流程，本文补的是两个方向的坑）。

## 存储位置

| 位置 | 内容 | 角色 |
|---|---|---|
| SQLite `data/charvar.db` → `subjects` 表 | `profile_json`（档案） | **运行时真源** |
| SQLite `data/charvar.db` → `subject_templates` 表 | `template_md`（通用提示词模板全文） | **运行时真源** |
| `presets/subjects/<id>.yaml` | 档案镜像 + derive 溯源头 | 仓库备份 |
| `presets/subjects/<id>.md` | 模板全文镜像（逐字） | 仓库备份 |

网页 `/subjects`、出图提示词拼装、主体档案页——**全程读 DB**。
`presets/subjects/*` 不参与运行时读取：只改仓库文件而不入库，网页上看到的还是旧档案，新文案不生效。

单条档案的字段（`charvar/models.py` 的 `SubjectProfile`，`extra="forbid"`）：
`id` / `name` / `subject_noun` / `trigger_word` / `reference_tag` /
`style_lock` / `identity_lock` / `outfit_lock` / `extra`（锁项是列表，`extra` 是自由文本）。

## 方向一：DB → 仓库（建档后备份）

`charvar subject export <id> [--dir <目录>] [--overwrite]`

写出 `presets/subjects/<id>.yaml`（DB 快照，文件头换成 export 标记）+ `<id>.md`（模板逐字、无改写）。
在 DB／网页建完档要记得 export——仓库里没有备份的档案，清库即失。

## 方向二：仓库 → DB（改了仓库文件后回灌）

**这一步最容易漏。** 仓库文件领先于 DB 时，运行时仍在用旧档案。

```bash
python3 -m charvar.cli subject add presets/subjects/<id>.yaml --overwrite
```

一条命令两张表都写：档案进 `subjects`，**同目录同名 `<id>.md` 模板逐字进 `subject_templates`**。

- `--template <路径>`：模板不在同目录时指定；
- 找不到模板 → **告警并只导档案**（DB 里旧模板保留，可能已过期）；
- `--json`：给脚本消费；
- 档案头里的 `sha256` 指纹与模板实际内容不符 → 告警（溯源链断了）。

模板也能单独维护：网页「主体档案 → 从 .md 文件载入」，或 `PUT /subjects/<id>/template`（body `{"template_md": "..."}`）。

`charvar subject derive <模板.md> --apply` 现在也把模板全文一并入库。

回灌后验三件事：

1. `python3 -m charvar.cli subject show <id>` —— 锁项条数与内容对得上；
2. `GET /subjects/<id>/template` 与 `presets/subjects/<id>.md` 逐字一致；
3. `POST /subjects/<id>/images/<kind>/suggest-prompt` 能起草（LLM 链路通）。

**别用 `subject export` 回灌**——方向反了：它按 DB 覆盖仓库，会用旧档案抹掉刚改的文件。

## yaml 头里的 sha256 溯源指纹

`charvar subject derive` 生成的 yaml 带一行来源指纹：

```yaml
# 来源模板：全场景通用提示词模板.md（sha256:ecc8d6ee9191）
```

它记的是**模板 md 的 sha256**。模板 md 改过（哪怕只是删一行注记）就要同步改这个指纹，
否则溯源链断掉、指纹与文件对不上。改完核对：

```bash
shasum -a 256 presets/subjects/<id>.md | cut -c1-12   # 与 yaml 头里的值应一致
```

## 图片槽位

5 个固定槽位（`front` / `headshot` / `side` / `behind` / `character_sheet`），
记录在 `subject_images` 表：落盘 `data/subjects/<id>/<kind>.{ext}`，`provider` 列记产出后端
（`comfyui` / `openrouter` / `dreamina` / 空＝上传）。

- `charvar/reference_images.py` 统一预处理参考图（长边 1536 / JPEG q88 / 透明白底合成），
  缓存键是 **mtime + size**，源图换了缓存自动失效重算，不会用旧参考图。
- 档案图与通用提示词模板是两条独立链路：模板写「哪个槽位用哪个模块」，图是模块跑出来的产物。
  模板升版（V1.0 → V1.1）后若槽位图还是旧版的，图与模板就对不上——要么按新模板重跑，
  要么在模板里写明「本目录的图仍是旧版」。
- 参考图槽位名从 mapping 读，不许写死节点 id。

## 一致性自查

```bash
# 仓库 ↔ DB 的 yaml 字段与 md 模板逐项比对
python3 - <<'PY'
import difflib
from pathlib import Path
import yaml as _yaml
from charvar import storage, paths

d = paths.presets_dir() / "subjects"
with storage.connect() as conn:
    subs = {r["id"]: r for r in conn.execute("SELECT id, profile_json FROM subjects").fetchall()}
    tpls = {r["subject_id"]: r["template_md"] for r in conn.execute("SELECT subject_id, template_md FROM subject_templates").fetchall()}

for sid, row in sorted(subs.items()):
    db = storage.SubjectProfile.model_validate_json(row["profile_json"]).model_dump()
    yml = _yaml.safe_load((d / f"{sid}.yaml").read_text(encoding="utf-8")) or {}
    bad = [f for f in db if db[f] != yml.get(f)]
    tpl = tpls.get(sid)
    md = (d / f"{sid}.md")
    md_ok = (not tpl) or (md.exists() and md.read_text(encoding="utf-8") == tpl)
    if bad or not md_ok:
        print(f"{sid}: 字段差异={bad} 模板一致={md_ok}")
PY
```

输出为空 = 仓库与 DB 全部对齐。
