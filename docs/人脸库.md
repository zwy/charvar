# 人脸库（data/faces/，第三方/自建多库）

给 AI 图片/视频统一「角色脸」的参考图库：AI 生成的**虚构人物**正面参考图（実在しない）。
数据真源在磁盘 `data/faces/<source>/`（catalog.json + img/full/*.png + img/thumb/*.webp，
由 `scripts/download_face_db.py --source <id>` 抓取，幂等续传），DB 表 `face_items`
只是索引 —— 丢失/损坏可整批重灌，重建成本接近零；收藏在独立用户层表
`face_favorites`（重灌绝不碰），文案未来单独建表。

- 首库 `face-db-01` = **AIモデル顔データベース**（https://ai-portrait-gallery.pages.dev/），
  运营 あぎ（[x.com/agi_aibusi](https://x.com/agi_aibusi)），1499 条：
  - `face`（フェイス）893 = 正面向き参考图（1122×1402 PNG）—— 用途「顔を揃える」；
  - `styling`（スタイリング）606 = 整体造型图（1597×2000，横版 6 张）—— 脸+发型+服装氛围。
- 发型类别 `hair` 4 档（ショート/ミディアム/セミロング/ロング = 短发/中发/中长发/长发），
  `style` 是日文发型细注（多数空）。中文名映射在 `charvar/faces.py`（SECTION_ZH/HAIR_ZH），
  全库字段存日文原文。

## 多库结构（同动作库）

登记表 `charvar/faces.py` 的 `FACE_SOURCES`：新库/自建库 = 加一行 + 下载脚本
`scripts/download_face_db.py` 的 `SITES` 表加站点（确认仍是 `data/images.js` 模板）。
DB 主键 `(source, face_id)`；图片路径跟随 `data/faces/<source>/`。

## 许可与分发（与 pose/costume 不同，注意）

- **CC0 1.0**：自由利用、商用 OK、编辑/参考 OK、无需署名、无保证
  （https://creativecommons.org/publicdomain/zero/1.0/deed.ja）。
- 图片是 AI 生成の架空の人物、実在しません；実在人物のなりすまし、公序良俗に反する
  用途は不可（同 pose 系红线：不得用于描绘实存人物）。
- 站方**请求**：「画像データそのものの再配布・転載はご遠慮ください（お願い）」——
  非禁令但站内明记。与 pose/costume 的「作者 X 公告允许二次发布」前提**不同**，
  本库数据**不随仓库分发**（`data/faces/` 进 .gitignore，仅本地使用）；
  是否改变由仓库持有人拍板。见 `data/faces/face-db-01/README.md`。

## 入库 / 浏览

```bash
python3 scripts/download_face_db.py                 # 抓取（幂等续传，trust_env=False 直连）
.venv/bin/python -m charvar.cli face import data/faces/face-db-01   # 灌 face_items（校验紧：图缺失/魔数错整批拒绝）
.venv/bin/python -m charvar.cli face list [--source --section --hair --q --json]
```

## 收藏（`face_favorites` 表：用户层）

- 表 `(source_id, face_id)` 主键，与 `pose_favorites` / `costume_favorites` 同型
  （用户态，face_items 重灌绝不碰）；`source_id` 沿 `face_items.source` 取值，
  新库/自建库 = 新 source 值，键位直接沿用不迁表。
- 读写：`faces.toggle_favorite`（favorite=None = 切换）；
  `POST /faces/{source}/{face_id}/favorite`；`GET /faces` 每条透出 `favorited`
  （前端计数现算）。
- 网页交互（对齐动作/服饰库，三库同款）：卡片右上「收藏 / 已收藏」文字徽章
  （点了不选卡、乐观更新 + 失败回滚）+ 形态页签行尾「♥ 收藏 (N)」筛选（0 收藏时
  隐藏；筛选开着收藏数归零自动回「全部」）+ 详情栏「收藏 / 已收藏」按钮，
  卡片↔详情同步。
- 三库搜索/筛选交互已归一（posegallery/costumegallery/facegallery 共用约定）：
  `type=search` 搜索框（带清除×），多词 AND 命中走 `core.js matchesQuery`
  （服饰库多带日文词表扩写，pose/face 的 haystack 本身中日双份），♥ chip 统一挂
  第二行（内容维度页签：系統/目录/形态）行尾。

## 生图接入（role=face）

参考图第五种来源：`ReferenceSpec.face_id`（+ `source` 选库，缺省 face-db-01），
role 缺省 `face`；前端「从人脸库加入」（genrefs.js showFaceBrowser，预设页与
Playground 共用）→ `/generate` 与 `/adhoc/generate` 服务端按 DB 行定文件、走
`reference_images` 统一压缩（原寸不过 1536 线直通转 JPEG）。

- **display_type = 条目 section（随条目存，不是随库）**：`face`=正面向き / `styling`=整体造型。
  LLM 锚定分句按它二选一：`llm_prompts` 四张 clause 表各挂 `face` / `face_styling`
  两键（组合形态下的措辞跟服装/发型预设让位 —— 服装组合表点名不抄图里服装、
  发型组合表点名发型结构归预设）。尾句：有姿势参考走 pose/depth 版；
  有人脸参考（无姿势）走 `REFERENCE_TAIL_SENTENCE_FACE`（同一个虚构人物 + 禁真人画像）。
- 经典模板模式不消费 face 参考的语义（仅校验文件存在）。
- **CLI 组合流（一库一张图）**：`charvar pose prompt <pose_id> --face <face_id>
  [--costume <item_id>] --run`（工作流①）与 `charvar costume prompt <item_id>
  --face <face_id> --run`（工作流②）—— face/styling 条目即 <image1> 身份锚，
  与 `--subject` 互斥；`--face` 支持唯一前缀与 `source/id` 前缀
  （`faces.resolve_face`）；体形锚 `--body-lock <句>`（仅 face 版生效）。
  classic 分段的 face 语义（身份句/身材锚/融合句的 face 版与组合分叉）在
  `charvar/pose_prompt.py`「人脸身份锚」块，与服饰工作流的其余五段机制复用；
  细则见 docs/服饰库.md「生图流程接入」。
- 实用组合：人脸（造型）+ 动作库姿势 + 主体/服饰 —— 三库同框给一个不存在的角色
  定脸、定姿、定衣。
