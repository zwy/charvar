# 视频放大（Playground「放大」页签 / charvar upscale）

「给一段已有视频把**短边**放大到目标档位」。adhoc 家族同构通路：网页（放大页签）与
CLI `charvar upscale comfyui|ffmpeg` 同一套参数语义、同一套落盘、同一份 manifest，
不落 runs 表；异步作业（提交 → manifest → `refresh` 收片）。

默认目标 = 短边 1080p；档位 `720p` / `1080p` / `4k`（4k = 短边 2160，与
`charvar.video._RES_SHORT` 同值同义）。

## 「短边已达标」规则

源视频短边 ≥ 目标档位时**原样复制返回，不入队**（两条后端同规则）。SeedVR2 是
超分修复模型，缩小或无增益重跑都不该发生。结果里 `passthrough: true`、
`multiplier: 0`。

## 两条后端

| | comfyui（SeedVR2） | ffmpeg |
|---|---|---|
| 画质 | 3B int8 超分修复（lanczos 先按倍数缩放，再过 SeedVR2 单步重建） | lanczos 插值 + libx264 crf18 重编码 |
| 速度 | ComfyUI 队列，几分钟级 | 本机秒级 |
| 作业 | prompt_id 进 `manifest.job.id`，refresh 轮询 `/history` 收片 | CLI = 同步 subprocess；web = 后台线程，refresh 只读 manifest |
| 默认链 | 请求显式 > 设置页「放大页默认」 > 兜底 workflow | 请求显式 > 设置页 > 兜底 1080p |

## ComfyUI workflow 与 mapping

成对文件 `data/workflows/utility_seedvr2_3b_int8_upscale_video.{json,mapping.json}`：

- `file` → LoadVideo（节点 id 来自 mapping，本模块不硬编码）；视频先
  `comfyui_exporter.upload_video`（`/upload/image` 端点对视频同样有效，
  LoadVideo widget 即 `video_upload`）进 ComfyUI input 目录，remote_name 带
  run_id 前缀（upload 端点 overwrite=true，重名会覆盖队列里的旧 prompt）。
- `multiplier` → ResizeImageMaskNode 的 `resize_type.multiplier`（dotted
  input_key 注入），值 = 目标短边/源短边（六位小数）；**放大倍数不是固定 2x**。
- `filename_prefix` → SaveVideo（`upscale/<run_id>`，按 run 隔离子目录）。
- SeedVR2 的 seed/tile/temporal 参数保持 workflow 原值（单步重建，seed 无意义）。

History 输出键：实测 SaveVideo 走 `images` 键（另有 `animated` 元数据键、LoadVideo
有 `has_intermediate_output` 预览输出 —— 所以**必须**靠 mapping 的 `output_nodes`
把收片范围定在 SaveVideo）；`_output_filenames` 仍兼容 `images`/`gifs`/`videos`
三键作安全网（VHS 类节点用 `gifs`）。

## 落盘与 API

- `data/generated/adhoc_upscale/{id}/`：original/ 成片 + thumbs/000000.jpg 海报 +
  manifest.json；run_id `ups_{时间戳}_{hex}`，严格正则（防 `..`，同 adhoc 家族）。
- 暂存输入池 `data/generated/adhoc_upscale/_inputs/`（网页上传，≤200MB，魔数判容器；
  ready 清理、24h 兜底 prune，与 adhoc 家族四件套同款）。
- API：`POST /upscales/upload`（→暂存 id）、`POST /upscales/generate`
  `{staged_id | video_run_id, backend?, target?}`（**二选一**）、
  `GET /upscales/{id}/status`、`GET /upscales`（X-Total-Count 翻页）、
  `GET /upscales/{id}/video|poster|manifest`。输入视频两个来源、**只认 id 不认路径**
  （浏览器永远不给路径）：`staged_id` = 上传暂存；`video_run_id` = Playground 视频
  run（「从最近生成加入」，服务端从 `adhoc_video.video_file` 落盘布局解析真实路径，
  「最近放大」列表显示该 run_id 当 `input_label`）。
- CLI：`charvar upscale comfyui <input> [--target] [--workflow] [--timeout 1800]` /
  `charvar upscale ffmpeg <input> [--target]`；`--out` 另落一份（纯复制不转码）。
- 设置页「放大页默认」组：backend / target / workflow（`settings_service.UpscaleSettings`，
  键 `upscale`；workflow 空 = 兜底 `utility_seedvr2_3b_int8_upscale_video`）。

## ffmpeg 细节

`scale=W:H:flags=lanczos`（宽高按 multiplier 各自取偶，yuv420p 要求偶数边）+
`libx264 -preset medium -crf 18 -movflags +faststart -c:a aac -b:a 192k`（音频统一
转 aac，防 opus 之类拷进 mp4 失败）。先写临时名，成功后原子改名（`.ups-` 前缀文件
不会被当产物读走）。

## 边界

- 网页 ffmpeg 后端是 web 进程里的后台线程：web 重启会丢作业（manifest 可能停在
  in_progress，重跑即可）；SeedVR2 作业在 ComfyUI 侧，重启不受影响。
- 不做批量多文件；不改 SeedVR2 workflow 的 tile/temporal 参数。
