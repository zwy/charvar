# 服装库（`data/costumes/`，第三方 costume-db-01）

「服装库」（网页顶栏「服装」页签）数据来自站点「衣装集 COSTUME-DB-01」
（https://ai-costume-gallery.pages.dev/）——与姿势库 pose-db-01 同作者（@giaaibusi）、
同套路（单页 HTML 内嵌 `const D=[...]` 数据数组）。服装是 **t2i 生成的架空服装**：
无人物、2:3 白底、每套一张图 + 一句英文关键词描述（提示词的服装原料）。
1407 套 × 8 目录（春215 / 夏254 / 秋244 / 冬253 / 内衣199 / 派对48 / 泳装54 / 性感系140）。
作者另有脸数据库与姿势数据库（姿势库即已接入的 pose-db-01）；`docs/服装库-作者文章.md`
是作者发布服装库的 X 文章全文 + 中文翻译。

- 图分三档：`thumbs/` 360×540 webp（缩略图）、`img/` 1366×2048 webp（详情图，
  网页展示用）、`png/` 1366×2048 无损原寸（后续参考图细部来源，不上网页）。
- 每条 catalog 行：`id`（如 `SPR-0001`，前缀=目录缩写 SPR/SUM/AUT/WIN/LNG/PTY/SWM/SXY）、
  `カテゴリ`（目录）、`キーワード`（英文服装描述 = 提示词原料）、`サムネ`/`画像`/`原寸`
  （三类图路径）。

## 许可红线

站点「注意点」原文要点：

- 可无偿使用（作品制作中的商用利用・编辑・参考 OK）；无需署名（任意）；图片元数据已删净、无保证。
- **禁止再分发图片数据本身（含原尺寸与加工后）**——与姿势库同款红线。
- 图片是 AI 生成的架空服装（全部 t2i，未用实存商品照片或参考图）；发布前做过与现有
  品牌的相似度检查，但不保证不侵犯他社权利，使用时各自确认判断。
- 不得用于描绘实际存在人物或未成年人、违反公序良俗的用途。

因此：图片与其目录**绝不进 git**（`data/costumes/` 已由 .gitignore 覆盖）；
`data/costumes/costume-db-01/README.md` 记录来源与许可要点，不动它。

## 数据与管线

- **磁盘 catalog 是「导入源」，DB 是运行时真源**：
  `data/costumes/costume-db-01/{catalog.json, glossary.json, thumbs/, img/, png/}`。
  catalog.json 逐字保留站点 D 数组（不许加字段）；glossary.json 逐字保留站点 JA 词表
  （日文检索词 → 英文关键词，104 条，站点检索的「日文词 → 英文关键词」桥）。
- **双表**（仿 pose 双表分层，pose_actions 红线同款）：
  - `costume_items` = 可重灌索引层（source_id + item_id 主键；站点库与自建库通用）：
    display_type / category / label / keywords / file_path(原寸) / image_path(详情) /
    thumb_path(缩略) / subject_policy(json) / caption_tags(json)。
  - `costume_prompts` = 用户文本层：prompt_text（文生图提示词）× source(manual/ai_draft)，
    **catalog 重灌绝不碰**。
  - 生图读法：条目引用 = `source/item` 或裸 `item`（唯一时，先查站点库）；「服装要点」
    注记取材 `note_text`＝文本层有值优先、否则 keywords；无图纯文本条目是合法状态
    （参考图解析显式报错，图锚定换装用纯文本换装通路）。
- 抓取：`scripts/download_costume_db.py`（幂等续传：文件在且魔数对就跳过，重跑即续传）。
  代理注意：外网抓取要走本机代理，**ALL_PROXY 是 socks5 而 httpx 缺 socksio 会
  ImportError**，脚本显式用 HTTP(S)_PROXY 的 http 代理 —— 与 exporters 的
  trust_env=False 红线不冲突（那条管内网 ComfyUI 地址）。
- 检索：服务端 q（id / 英文关键词 / 中日目录名，大小写不敏感；日文词经 glossary 扩写成
  英文一并命中）与前端本地过滤同一套语义；glossary 随 `GET /costumes` 返回给前端。
- catalog 校验红线：路径只认 `(thumbs|img|png)/{item_id}.{ext}` 布局、id 只认安全字符
  （[A-Za-z0-9_-]）——路径拼不过校验整批拒绝，`../` 逃逸进不来；import 时再验图在盘 +
  魔数（thumbs/img 必须在，png 可选在则验）。

### CLI 与导入命令（一期）

| 命令 | 干什么 |
|---|---|
| `charvar costume import` | catalog+侧车 → `costume_items` 幂等重灌（1407 条；缺图/魔数不符整批拒绝） |
| `charvar costume import-studio` | `presets/costumes/studio/` 镜像 → 自建行（insert-if-missing，含 sort_order 家族次序；**已存在整条跳过**——不覆盖 DB 里改过的编辑）。镜像由 `costume export` 维护；presets/outfits 的 yaml 已退役 |
| `charvar costume prompt-text <ref> [--set '…']` | 读/写文本层（空串 = 清掉该条文本；source=manual） |
| `charvar costume describe <ref…> [--limit/--overwrite/--dry-run/--model]` | LLM 看缩略图起稿 t2i 提示词落库（source=ai_draft；按 display_type 说明展示形态；幂等跳过已写条目） |
| `charvar costume export <ref> [--out DIR]` | 单条（含文本层）快照回 `presets/costumes/<source_id>/<item_id>.yaml`（DB 是运行时真源，仿主体档案 export） |

**服装家族（B5：outfit.py 的 DB 视图）**：`/generate` 带 `outfit_preset`（网页/CLI
`gen --outfit`/recipes）读的全是这张表 —— 家族 = studio 条目的 `category` 列，条目
次序 = `sort_order`（组合变体次序 = reel 播放次序），条目 `text` = 文本层 `prompt_text`
优先、回退 `keywords`（DB 里编辑实时进批）。旧 `presets/outfits/*.yaml` 家族文件
**退役**：镜像在 `presets/costumes/studio/`（28 条，`costume export` 维护、
`import-studio` 重建）；镜像只补缺行、不覆盖用户编辑。服装从此只有一个系统：
带图的站点库条目（图+文本双锚）与纯文本家族条目（文本锚）都是 `costume_items` 行。
- **自建条目的图**：28 条里 24 条已补平铺参考图（ComfyUI 2K 3:4，1792×2400），
  沿站点三档落 `data/costumes/studio/{png,img,thumbs}/`（img 档长边 2048、thumbs 宽
  360；镜像 yaml images 段带路径，重建随行）。`character_outfit_debug` 4 条**保持
  无图纯文本**（仅内裤 / 无衣物 / 保留原衣物这类策略测试条款没有实体可画——无图
  纯文本是合法状态）。工作流②实测 2 条（丝袜 / 比基尼，同种子）：平铺两件正确
  组合穿着、无凭空配件。

- **来源页签**（全部 / 站点库 / 自建库）：站点库 1407 条（2:3、ghost）与自建库 28 条

  （站点条目缺省回 id）+ mono id + 「平铺」徽章（仅 flat_lay 标）+ 关键词预览；无图

## 生图流程接入（CLI：两条工作流）

参考图语义 role=`costume`：**只锚服装**（款式/配色/面料/层次），脸、发型、体型、
姿势全部来自主体档案与其它参考图；图库里是 t2i 架空服装、无人物，天然是干净的服装锚。
发送走统一压缩线（长边 1536 / JPEG q88；源文件 `png/` 无损原寸优先、缺则回退
`img/` webp —— 同像素只差编码），缓存 `data/costumes/costume-db-01/_ref_cache/costume_{id}.jpg`，
mtime+size 失效判定同主体图。服装锚定/融合/换装禁令文案都在 `charvar/pose_prompt.py`
（与姿势拼装同源，别在前端另造）；catalog 行的 `原寸` 字段已进校验（有值才校验）。

- **① 单主体 + 单人动作 + 服装**：`charvar pose prompt <pose_id> --subject <id>
  --costume <item_id> --run`。参考图序 = [主体， 动作线稿， 服装] = <image1>/<image2>/<image3>；
  image1 锚定句自动换服装版（锚身份不锚服饰，配饰冲突以服装参考为准）；双人（2人絡み）
  + `--costume` 显式报错（双人换装二期）。
- **② 单主体 + 服装（无动作）**：`charvar costume prompt <item_id> --subject <id> --run`。
  参考图序 = [主体， 服装] = <image1>/<image2>；姿态不锚（模型自选自然站姿），
  全身构图句与换装禁令与①同源。
- **身材锚（通用问题的定点解）**：服装图是「穿在身上的衣服」，自带隐含身体
  模板 —— 不锚身材的话，身材会随服装图走（实测：服装模特身替代角色身）。
  两条工作流的服装锚之后固定一段（`pose_prompt._figure_anchor`）：**身材/
  身高/四肢比例一律以 <image1> 为准，服装按 image1 身材重新合身**；注意
  锚句里不能把服装图降权成「只提供款式与面料」—— 实测那样写后整套搭配的
  配件（鞋/包/帽）会跟着掉；要写成「整套搭配（含鞋袜包帽）都要保留」。
  主体档案 `body_lock`（英文体形锚，derive 自动生成，可缺省）原文拼进来当
  第二层锚。老档案缺 body_lock 时仍有第一层 —— 建议用 `charvar subject
  derive` 或手写补上。
- **配件锚（主锚内的配件层，A/B 实测定稿）**：只写「完整还原该套服装」的话，
  帽子/包会整件丢 —— 根因是**参考图是无头人台展示，帽子悬空摆放**，模型不把
  悬空件当成「要穿的」。定稿锚写三层：配件枚举（鞋/袜/帽/围巾/手套/包 → 款式
  与用法）+ **点名悬空展示件**（「参考图中单独摆放或悬空放置的配件也是这套造型
  的组成部分，要装到角色身上」+ 戴头/围脖/挎肩方位）+ **清单绑定显著性句**
  （「清单上列出的每件都要出现在画面里」——注意**不要枚举类别名**如「帽子、围巾、
  包要出现在画面里」：服装本来没有包时那会凭空召唤出一个包，实测复现）。锚尾
  「不额外添加无关装饰」**保留**：拦凭空发明（平铺 A/B 实测无禁句会发明挎包），
  对配件采纳中立（昨天 B/D 组证据）。方位句单独加没有用（0/5 那轮就有方位句）
  —— **点名悬空机制是钥匙**。全部正向措辞，别写否定式（显性召唤物反噬）。
  手被占住的姿势（双臂收前）包无处安放是姿势依赖（与 C9 同族）。
- **展示形态（display_type）**：参考图分两种陈列态 —— `ghost`（隐形模特：无头无身、
  服装保持穿着立体形态悬空陈列；站点实测全库都是这种形态）/ `flat_lay`（平铺展示：
  俯视平铺、衣物分开平放）。数据放**侧车文件** `display_types.json`（服装库目录下，
  `{item_id: 类型}`，缺省缺条 = ghost）；catalog.json 逐字保留红线不动；缓存键 =
  catalog + 侧车双 mtime+size；坏值/坏 id 整批拒绝。提示词分叉（`pose_prompt._DISPLAY_FORM_CLAUSES`，
  插在服装锚之前的一句「这张图是什么」，typo 直接 ValueError）：ghost 说「没有头和身体，
  服装保持穿上时的立体形态悬空陈列」（与悬空配件机制句衔接）；flat_lay 说「衣物分开
  平放是展示方式，不是穿着效果；按穿搭关系在角色身上正确组合穿着，成图是正常人体
  视角」——**平铺必须显式做「平铺并列 → 穿着组合」的语义转移**，还要防俯视构图串味。
  `GET /costumes` 行透出 `display_type`（网页徽章二期）。新 flat-lay 条目接入时按
  同法先 A/B 一发再定稿。
- 公共参数同 `pose prompt`（`--backend/--aspect/--resolution/--seed/--out/--negative/--wait/--json`）。
- catalog 的英文 `キーワード` 拼「服装要点」注记行进提示词（`pose_prompt._costume_keywords`，
  原文不译写，位置在服装锚与身材锚之间）：部件清单按行核对（「不缺件、不改部件类型」）。
  实测（WIN-0001 × 坐姿/站姿，同主体同种子）：外套等大件在注记后稳定回归；服装部件类型
  在动作**不与廓形冲突**时正确（站立姿势长裙正确还原）。但注记压不住**动作×服装廓形的
  结构冲突** —— 张腿坐姿把鱼尾长裙稳定读成阔腿裤（两个种子复现），模型以动作优先；
  头上配件（贝雷帽）也常被主体发型压掉。这类冲突归待完善清单 C9，不是注记能解的。
  关键词为空时注记整节消失（回退纯图锚定）；仍是网页复制与文本换装
  （charvar/outfit.py 那条通路）的原料。

## 与姿势库的差异（二期集成时注意）

- **单图、无视角双键**：参考图组合是 `(item_id)` 一元，没有 angle 维度。
- **无名称字段**：展示与检索都靠 item_id + 英文关键词；中文对照表（姿势库的
  pose_translations 同类物）v1 未做。
- **语义是「服装锚」**：服装图锚服装（脸/姿势/身份仍来自主体档案与其它参考图），与
  pose 的「姿势锚」互补。keywords 是英文、按服装段规则整段进提示词不译写（与
  `charvar/outfit.py` 的服装段「语言不限、不译写」约定一致）。
- 「换装要解旧衣物锁」（`subject_policy`）与服装参考图接入时走同一套。
