# 姿势库（`data/poses/`，第三方 pose-db-01）

「动作库」参考图来源：站点「ポーズ集 POSE-DB-01」（https://ai-pose-gallery.pages.dev/）的
灰色无脸人偶线稿。288 个动作 × 5 视角（正面/上から/横/斜め/下から；一个动作缺 1 张下から），
共 1439 张。两级结构：动作（系統+ポーズ番号+ポーズ名+分類）下挂 1–5 张「动作×视角」图。

- 四个系統：全身1人・セクシー系（80 动作）/ 全身1人・標準系（73）/ 上半身1人（80）/
  2人絡み（55，**双人构图**，用于多人物出图）。
- 分類 26 种（立ち/座り/寝そべり/かわいい系/…，2人絡み 线带体位类分類）。
- 图：原寸 PNG 900×1200（`img/`）+ JPEG 缩略图 300×400（`thumbs/`）；
  过 `reference_images` 预处理线（≤1536），发送前只转 JPEG 不缩放。

## 许可红线

站点许可原文要点：作品制作可免费**商用**、可编辑、可参考，无需署名；
**禁止再分发图片数据本身**（含元尺寸与加工后）；不得用于描绘真人或未成年。

因此：

- 图片与其目录**绝不进 git**（`data/poses/` 已由 .gitignore 覆盖）。
- `data/poses/pose-db-01/README.md` 记录来源与许可要点，不动它。

## 数据与管线

- 磁盘是真源：`data/poses/pose-db-01/{catalog.json, img/, thumbs/}` —— catalog.json
  逐字保留站点内嵌数据（8 字段全日文原文：id / 系統 / ポーズ番号 / 分類 / ポーズ名 /
  アングル / サムネ / 原寸）。
- 抓取：`scripts/download_pose_db.py`（幂等续传：文件在且魔数对就跳过；代理红线同
  exporters —— trust_env=False 绕过本机 ALL_PROXY）。
- 入库：`charvar pose import [目录]` → `pose_images` 表（幂等 upsert，整批校验：
  id 字符集 / 视角枚举 / 文件齐全与魔数，任一异常整批拒绝）。浏览：`charvar pose list`
  （`--line` / `--category` / `--q` / `--json`）。
- DB 表 `pose_images` 只是索引（pose_id = 站点条目 id 去视角后缀，如 `full_sexy_P001`；
  `(pose_id, angle)` 主键；pose 级字段冗余成列）。索引坏了 → 重灌，成本接近零。
- 中文名（`ANGLE_ZH` / `LINE_ZH` / `CATEGORY_ZH`）是 `charvar/poses.py` 里的映射，
  **存储只存日文原文**；未知原文回退原文。视角/系統的站点固定次序用 `ANGLE_ORDER` /
  `LINE_ORDER`。

## 参考图通路（role=pose）

- `ReferenceSpec` 第四来源：`pose_id` + `angle`（angle 缺省正面）。只认 DB 里的组合，
  文件名由服务端从 DB 行与站点落盘布局定 —— 浏览器不给路径（其它三种来源同一原则）。
- **role 固定 `pose`**：这库只锚**姿势与构图**，不锚任何身份外观 —— 脸/发型/服装/配色
  都来自主体档案或其它参考图。
- LLM 改写：四张锚定句表（base / outfit / hairstyle / outfit+hairstyle）各有 pose 分句
  （mannequin 线稿语义）；有 pose 参考时尾句换 `REFERENCE_TAIL_SENTENCE_POSE` ——
  旧尾句的「create a new pose / One character only」与姿势参考正相反（2人絡み 线要
  双人，人数跟随参考图）；「never render a gray mannequin」排线稿风格污染。
  body_lock 体形锚不吃 pose 图（人偶没有可核对的体形，锚挂第一张非 pose 参考图）。
- classic 模式：图直通两条生图通路（ComfyUI edit workflow / OpenRouter i2i 组），
  与其它参考图同语义（带参考图 = 图片编辑）。缓存键 = 站点条目 id
  （`pose_{pose_id}_{后缀}` —— 视角原文是 CJK，别用视角映射当缓存键，会相撞）。
- 网页：预设页与 Playground 参考图区「从动作库加入」（共用 `GenRefs.showPoseBrowser`，
  渲染抽在 `web/static/posegallery.js`）；顶栏「动作」页签另有整页版 `posepage.js`
  —— 弹层/整页同源渲染。后端 `/poses*`（`charvar/api.py`）：`GET /poses`
  （清单 + 元数据 + 各动作 action_text）、`GET/PUT /poses/{pose_id}/action`、
  `GET /poses/image/{source}/{pose_id}/{angle}/thumb|full`。

## 中日对照展示

- 动作名中文译表 = `charvar/pose_translations.py` 的 `POSE_TITLE_ZH`（288 条，自有内容
  进 git —— 许可只限图片数据）；`poses.title_zh()` 缺项/空译文都回退日文原文。
  展示形态：中文为主阅读层、日文 muted 小字并列（网格卡与详情栏同构）。
- 搜索词中日皆可命中（haystack 同时含 title 与 title_zh）。
- `tests/test_poses.py::test_title_zh_covers_real_catalog_when_present` 会拿真实
  catalog 校验译表覆盖度 —— 站点加新动作时译表缺项在这里先炸。
  网格行的收缩红线见 style.css `.pose-grid` 注释（`overflow:hidden` 卡片会让
  auto 行高按一行文本收缩、卡片逐行压叠）。
- **暂不接**：视频首帧/参考视频（人偶与角色一致性语义冲突）、贴字、配方步 ——
  需要时再议。「同动作多视角叠加成多张参考图」仍为二期；
  「ポーズ名→action 预设草稿」的存储已落（见下节动作描述），AI 起草初稿是后续。

## 动作描述（`pose_actions` 表）

- 每个动作一条的中文动作描述提示词（例：P001「身体基本朝向镜头，腰胯轻微扭转，
  呈自然的 S 形曲线；……」），存独立表 `pose_actions`（pose_id 主键 + action_text
  / source / created_at / updated_at）。**不塞 `pose_images`**：那是可整批重灌的
  站点索引（`pose import` 幂等 upsert 整批覆盖、主键是 (pose_id, angle) 视角维度），
  用户文案与索引分层，重灌零影响。
- 读写：`poses.pose_action` / `poses.set_pose_action`（**空串 = 清掉条目**；
  pose_id 必须在库内 —— 非法 id 400、库里没有 404）；`GET /poses` 每动作多带
  `action_text`（LEFT JOIN，缺省空串），搜索命中动作描述（中日皆可搜）。
  端点：`GET/PUT /poses/{pose_id}/action`。
- 展示：详情栏「动作描述」块（有 → 文本 + 复制按钮；无 → 灰字一句）、卡片
  「描述」角标；弹层与整页同源共用（`posegallery.js` 单份渲染）。
- 后续挂这张表：编辑 UI（textarea + PUT）、AI 起草初稿（source=ai_draft）、
  生成接入（选 pose 参考图时带出描述当动作文本草稿）。
