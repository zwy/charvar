# 姿势库（`data/poses/`，第三方多库）

「动作库」参考图来源：同作者（ギア）的姊妹站系列，同一站式单页模板、同一批
288 个动作 × 5 视角（正面/上から/横/斜め/下から；一个动作缺 1 张下から，每库
1439 张）。两级结构：动作（系統+ポーズ番号+ポーズ名+分類）下挂 1–5 张
「动作×视角」图。多库结构：库登记在 `charvar/poses.py` 的 `POSE_SOURCES`
（source_id → 展示形态 display_type / 中文标签）。

- `pose-db-01` = 线稿库（https://ai-pose-gallery.pages.dev/，灰色无脸人偶**线稿**）。
- `pose-db-02` = 深度库（https://ai-pose-depth-gallery.pages.dev/，同一 pose 集的
  灰**深度图**，白=近；锚前后遮挡关系）。**与线稿库同 id、同词表** ——
  `pose_images` 主键 `(source, pose_id, angle)`，用户层（描述/收藏）按库分键。
- 四个系統：全身1人・セクシー系（80 动作）/ 全身1人・標準系（73）/ 上半身1人（80）/
  2人絡み（55，**双人构图**，用于多人物出图）。
- 分類 26 种（立ち/座り/寝そべり/かわいい系/…，2人絡み 线带体位类分類）。
- 图：原寸 PNG 900×1200（`img/`）+ JPEG 缩略图 300×400（`thumbs/`）；
  过 `reference_images` 预处理线（≤1536），发送前只转 JPEG 不缩放。
- 新库/自建库：`POSE_SOURCES` 加一行（display_type：线稿 `line` / 深度 `depth`，
  新值须配 `llm_prompts` 的参考分句）+ `scripts/download_pose_db.py` 的 `SITES`
  表加站点（同一页模板即可抓）——DB 不用迁表；自建库直接把 catalog.json +
  图画布好再 `pose import`。

## 许可与分发

站点许可原文要点（两站现行一致）：無償で利用できます（作品制作での商用利用・
編集・参考利用OK）、クレジット表記不要、無保証；不得用于描绘真人或未成年。

图片数据的再分发：**作者在 X 上公告允许二次发布**（フリー素材として公開、
商用利用OK）—— 本项目据此把三个图片库（pose-db-01/02、costume-db-01）随仓库
公开分发。每库 `data/poses/<source>/README.md`（服饰库同）记录来源与许可要点。

## 数据与管线

- 磁盘是真源：`data/poses/<source>/{catalog.json, img/, thumbs/}` —— catalog.json
  逐字保留站点内嵌数据（8 字段全日文原文：id / 系統 / ポーズ番号 / 分類 /
  ポーズ名 / アングル / サムネ / 原寸）。
- 抓取：`scripts/download_pose_db.py --source <库id>`（幂等续传：文件在且魔数对
  就跳过；代理红线同 exporters —— trust_env=False 绕过本机 ALL_PROXY）。
- 入库：`charvar pose import data/poses/<source>` → `pose_images` 表（库 id 取
  目录名，必须已登记；幂等 upsert，整批校验：id 字符集 / 视角枚举 / 文件齐全
  与魔数，任一异常整批拒绝）。浏览：`charvar pose list`（`--source` / `--line` /
  `--category` / `--q` / `--json`）。
- DB 表 `pose_images` 只是索引（pose_id = 站点条目 id 去视角后缀，如
  `full_sexy_P001`；`(source, pose_id, angle)` 主键 + `display_type` 列；
  pose 级字段冗余成列）。索引坏了 → 重灌，成本接近零。
- 中文名（`ANGLE_ZH` / `LINE_ZH` / `CATEGORY_ZH`）是 `charvar/poses.py` 里的映射，
  **存储只存日文原文**；未知原文回退原文。视角/系統的站点固定次序用 `ANGLE_ORDER` /
  `LINE_ORDER`；两库词表相同，译直接共用。

## 参考图通路（role=pose）

- `ReferenceSpec` 第四来源：`pose_id` + `angle`（angle 缺省正面）+ `source`（库 id，
  缺省 pose-db-01 —— 存量 run 的规格无此字段自动回退）。只认 DB 里的组合，
  文件名由服务端从 DB 行与站点落盘布局定 —— 浏览器不给路径（其它三种来源同一原则）。
- **role 固定 `pose`**：这库只锚**姿势与构图**，不锚任何身份外观 —— 脸/发型/服装/
  配色都来自主体档案或其它参考图。
- LLM 改写：四张锚定句表（base / outfit / hairstyle / outfit+hairstyle）各有 pose 分句
  （mannequin 线稿语义）+ `pose_depth` 分句（深度图语义，白=近）；按参考图的
  display_type 二选一，有 pose 参考时尾句换 `REFERENCE_TAIL_SENTENCE_POSE` /
  `_POSE_DEPTH` —— 旧尾句的「create a new pose / One character only」与姿势参考
  正相反（2人絡み 线要双人，人数跟随参考图）；禁令排线稿/深度图风格污染。
  body_lock 体形锚不吃 pose 图（人偶没有可核对的体形，锚挂第一张非 pose 参考图）。
- classic 模式：图直通两条生图通路（ComfyUI edit workflow / OpenRouter i2i 组），
  与其它参考图同语义（带参考图 = 图片编辑）。缓存键 = 站点条目 id
  （`pose_{pose_id}_{后缀}` —— 视角原文是 CJK，别用视角映射当缓存键，会相撞；
  缓存目录按库分，键不跨库冲突）。
- 网页：预设页与 Playground 参考图区「从动作库加入」（共用 `GenRefs.showPoseBrowser`，
  渲染抽在 `web/static/posegallery.js`）；顶栏「动作」页签另有整页版 `posepage.js`
  —— 弹层/整页同源渲染。后端 `/poses*`（`charvar/api.py`）：`GET /poses`
  （全库清单 + 每库系統/分類元数据 + 各动作 action_text + favorited）、
  `GET/PUT /poses/{source}/{pose_id}/action`、`POST /poses/{source}/{pose_id}/favorite`、
  `GET /poses/image/{source}/{pose_id}/{angle}/thumb|full`。

## 动作描述（`pose_actions` 表：库×动作×视角 键）

- **按「库×动作×视角」存**（主键 `(source_id, pose_id, angle)`；存量化单键/双键
  的旧形状，启动时 `storage._rebuild_pose_actions_pk` 整表重建、存量库 id 回填
  pose-db-01、动作级旧描述迁到正面）。为什么视角级：
  描述里的画面事实（「身体朝向镜头」「画面右侧的手臂」、俯拍透视）只对单一
  机位成立，而参考图一选定就是视角级的 —— **视角不回退**，没写就是没写
  （回退 = 文本-图错配）。写作节奏：正面先写、用到哪个补哪个；编辑时可
  「从其他视角复制」再改（后续做）。
- 表含 source_id / pose_id / angle / action_text / source / created_at /
  updated_at；**不塞 pose_images**：那是可整批重灌的站点索引（`pose import`
  幂等 upsert 覆盖），用户文案与索引分层，重灌零影响。
- 读写：`poses.pose_action` / `poses.set_pose_action`（**action_text 空串 = 清掉
  该视角条目**；非法 id/视角 400、库里没有该组合 404）。`GET /poses` 的
  `action_text` 挂在每条 `images[]` 视角上（缺省空串），搜索命中任意视角的
  描述（中日皆可搜）。端点：`GET/PUT /poses/{source}/{pose_id}/action`
  （PUT body 带 angle，缺省正面）。**同一 pose_id 两库各有描述**（按库分键），
  depth 库的描述独立维护（AI 起稿/网页编辑都可以）。
- 展示：详情栏「动作描述 · 〈视角中文〉」块跟随所选视角（有 → 文本 + 复制；无 →
  灰字空态）；弹层与整页同源共用（posegallery.js）。网页编辑 = 详情栏 textarea +
  保存/取消（PUT 落 `source=manual`，空串 = 清掉该视角条目）；换视角 / 换动作即
  退出编辑态（草稿不跨条目）——描述逐视角写，动笔前先看该视角缩略图。
- 后续挂这张表：「从其他视角复制」种子句、AI 起草初稿（source=ai_draft）、
  生成接入（带 pose 参考图时按所选视角带出描述当动作草稿）。

## 收藏（`pose_favorites` 表：用户层）

- 表 `(source_id, pose_id)` 主键，与 `costume_favorites` 同型（用户态，pose_images
  重灌绝不碰）；`source_id` 按库分键 —— 线稿库/深度库各自的收藏独立（同 id
  两库是两个浏览条目）；新库/自建库 = 新 source 值，键位直接沿用不迁表。
- 读写：`poses.toggle_favorite`（favorite=None = 切换）；
  `POST /poses/{source}/{pose_id}/favorite`；`GET /poses` 每动作透出 `favorited`
  （前端计数现算）。
- 网页交互（对齐服饰库）：卡片右上「收藏 / 已收藏」文字徽章（点了不选卡、乐观
  更新 + 失败回滚）+ 系統页签行尾「♥ 收藏 (N)」筛选（0 收藏时隐藏；筛选开着
  收藏数归零自动回「全部」）+ 详情栏「收藏 / 已收藏」按钮，卡片↔详情同步。
  卡片上的「描述」角标（原 pose-desc-badge）已移除——写没写描述看详情栏，
  全库搜索仍命中描述文本。

## 动作描述 → 直通出图（CLI：`charvar pose prompt`）

- 提示词结构（用户定稿的画面版 demo，`charvar/pose_prompt.py`）：两段参考图锚定
  → 「让 image1 角色摆出 image2 姿势：{该动作该视角的动作描述}」→ 构图句 →
  背景句 → 禁令句，段落间空行。`--source pose-db-02`（深度库）时姿势参考段
  换深度图措辞（锚前后遮挡，白=近；禁令点名别画成人偶/深度图）。
- **分段按库线型给版本**（`LINE_KIND`：全身1人两系=full / 上半身1人=upper /
  2人絡み=pair）：构图句（全身不裁肢体 / 半身取头顶到大腿、不裁手指 / 双人
  全身两人）、禁令句（双人加「画面固定为两个角色、不多不少」）、双人版
  image1 锚定句点明「两位角色都沿用该角色外观与服装」。背景/光照先固定
  「背景简洁，突出角色。」—— 后续接 `presets/wildcards` 的 backgrounds/lighting
  池再参数化（随机必须走 `charvar.wildcard.seed_for`）。
- CLI：
  - `charvar pose action <pose_id> [--angle 正面] [--set '描述' | 无 --set 读]`
    —— 动作描述的数据入口（动作×视角 双键，空 --set... --set 空串 = 清）。
  - `charvar pose prompt <pose_id> [--angle]` —— 拼装并回显提示词；
    `--subject <id> [--subject2 <id>] [--costume <item_id>] --run [--backend/aspect/resolution/seed/out]`
    —— 主体槽位图 = <image1>（**上半身动作取 headshot**，缺则回退 front；
    全身/双人取 front），该动作该视角的预处理线稿 = <image2>
    （reference_paths 顺序即槽位顺序），走 Playground 通路出图。该动作视角
    没写描述时报错并给写入命令；**双主体**：2人絡み 给 `--subject2` 时
    <image1>/<image2> 分别锚定描述里的「甲」「乙」、动作线稿顺移成
    <image3>；不给 = 甲乙都沿用 <image1>（lead 点明）。**服装**：单人生效，
    `--costume <item_id>` 服装图 = <image3>（双人报错）—— 锚定/融合/禁令与
    参考图预处理见 docs/服饰库.md「生图流程接入」。**人脸身份锚**：
    `--face <face_id>`（支持唯一前缀与 `source/id` 前缀，与 --subject/--subject2
    **互斥** —— 两个身份来源的图会揉脸；双人报错）—— face/styling 条目即
    <image1>（三库组合流 = --face + 姿势 + --costume，一库一张图）；styling 段
    与主体档案同锚定文本，face 段（正面胸像）用 face 版身份句/身材锚/融合句
    （charvar/pose_prompt.py「人脸身份锚」块）；体形锚 `--body-lock <句>`
    （可多次，仅 --face 生效）。
- **双人描述的写法约定**：文案自带「甲（位置/角色说明）」「乙（…）」标签
  （例：pair60_P010 正面「甲（后方人物）坐在地面…乙（前方人物）侧坐在甲的
  膝上…」）—— 担当局由提示词映射成 image1/2，描述里不写死 imageN。
- **视角级描述写法模式**（15 条实测范式）：身体事实（同一动作各视角共享：
  四肢怎么摆、重心在哪）+ 机位事实（俯/仰/侧带来的朝向句、近端遮挡、透视
  大小）——写每条前先看该视角缩略图核对遮挡与朝向，别从正面文本机械改写。
- 网页接入（沿用同一模块与数据）是后续 —— 前端把「加入参考图/编辑」接到
  `build_prompt` 上，不在两条通路外再造分段文本。

## 动作描述怎么写（方法记录 + LLM 批量起稿）

**人工范式**（先手工定稿的批次＝样板：67 条正面 + 2 个动作的全视角 15 条）：

- 每条动笔前先看该视角缩略图（`data/poses/pose-db-01/thumbs/<id>_<front/high/
  side/diag/low>.jpg`），别从正面文本机械改写；
- 内容 = **身体事实**（四肢/躯干/头怎么摆、重心与承重腿）+ **机位事实**
  （朝向句「面朝画面左方」、俯/仰机位说明、近端遮挡与透视大小）；80–160 字一段；
- **手势/局部位置要给高度锚**（同种子只改文本实测）：只写「手举到左脸侧」
  会在 headshot 锚下降到肩部；写「手掌贴在左脸颊、指尖齐眉、与头同高」
  贴脸成稿（upper80v2_P005，seed 7/42 双验）。取景外的事实（上半身动作的
  腿/重心/脚）别写 —— 看不见的内容会稀释取景内的关键动作；
- 不写身份/服装/表情/画风 —— 人偶没有这些，身份全部来自主体档案与其它参考图；
- 双人（2人絡み）强制「甲（位置说明）」「乙（位置说明）」指称（甲乙约定见上节）；
- 写入/改稿：`charvar pose action <pose_id> --angle <视角> --set '描述'
  [--source <库>]`（不写 --set 即读取；--set 空串 = 清；缺省线稿库）。

**LLM 批量起稿**（`charvar/pose_describe.py`；写入记 `source=ai_draft`）：

```bash
python3 -m charvar.cli pose describe --limit 5 --dry-run   # 试稿看质量
python3 -m charvar.cli pose describe                       # 缺描述的全部起稿落库
python3 -m charvar.cli pose describe --source pose-db-02   # depth 库（按库扫）
python3 -m charvar.cli pose describe --model <视觉模型>     # 默认 LLM 无视觉时换模型
```
- 流程：取浏览次序下缺该视角描述的动作（**只扫所选库**）→ 缩略图转 data URL 进
  多模态 messages → LLM 起稿 → 校验（中文必有 / 30–400 字 / 双人必须有甲乙 /
  无身份词）→ `set_pose_action(source=ai_draft)`；**已写的自动跳过**，中断或失败
  重跑同一命令即续传；`--overwrite` 重写已写条目。
- 样板 = 模块内 `FEWSHOT`（5 条代表例：用户原稿 P001 / 单腿抱膝 / 前屈侧面 /
  半身比心 / 双人甲乙）。起稿是 ai_draft —— 用于出图前建议人工抽看
  （`charvar pose action <id>` 或浏览页面），不对就 `--set` 改正。
