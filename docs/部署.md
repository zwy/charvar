# 部署指南（全新克隆 → 跑起来）

本文包含基础安装、配置、启动、可选本地素材导入、首次部署检查及常见问题。

完成第 1–3 节即可检查基础服务是否可用。参考库初始化、出图后端和视频处理工具均按需配置，不是启动网页的必需条件。

## 0. 前置条件

| 项目 | 要求 | 说明 |
|---|---|---|
| Python | 建议 3.11 或以上 | 原部署记录验证过 3.12.8；其他版本请自行验证依赖兼容性 |
| screen | 使用后台启动脚本时需要 | 先执行 `screen --version` 检查；Linux 可通过系统包管理器安装 |
| ffmpeg | 可选 | 视频合成等相关功能需要 |
| 磁盘 | 按用途预留 | 依赖、生成结果和可选本地素材分别占用空间；无需为基础启动下载完整第三方图库 |

出图后端按需选择；不配置时仍可启动网页，但相应生图功能不可用：

- ComfyUI：配置 `COMFYUI_HOST` / `COMFYUI_PORT`。
- OpenRouter：配置在线生图或 LLM 所需的 API Key。
- 即梦 Dreamina：安装 CLI 并在运行服务的环境中完成登录，见第 6 节。

第三方素材来源与使用限制见 [README：第三方参考资源](../README.md#第三方参考资源)和[第三方素材与使用边界](../README.md#第三方素材与使用边界)。

## 1. 建立虚拟环境并安装依赖

在项目根目录执行：

```bash
cd /path/to/charvar
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

启动器和全局 CLI 优先使用仓库内的 `.venv/bin/python`；找不到时可能退回系统 `python3`。建议始终创建虚拟环境，以避免解释器版本与依赖环境不一致。

检查解释器及 pip 所属环境：

```bash
.venv/bin/python --version
.venv/bin/python -m pip --version
```

`requirements.txt` 应包含运行时所需依赖。若服务启动时提示缺少 `python-multipart` 等模块，先确认依赖确实安装到了上述虚拟环境，而不是系统 Python。

## 2. 配置 `.env`

首次部署时，从模板创建配置；已有 `.env` 时请保留原配置，不要直接覆盖：

```bash
cp .env.example .env
```

按需编辑 `.env`，完整键位以当前 `.env.example` 为准。

### ComfyUI（可选）

```env
COMFYUI_HOST=127.0.0.1
COMFYUI_PORT=8188
COMFYUI_TIMEOUT=180
COMFYUI_WORKFLOWS_DIR=./data/workflows
```

### LLM / OpenRouter（可选）

```env
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=填写你自己的密钥
LLM_MODEL=填写当前可用的模型ID
```

独立的在线生图配置、供应商参数及模型兼容性见 [README](../README.md)。不要把模型示例当作长期可用性保证。

注意：

- `.env` 不应提交到 Git，也不要在 Issue、截图或日志中公开密钥。
- 已存在的环境变量可能优先于 `.env`。
- 部分网页设置保存于数据库，可能覆盖环境变量；以相关功能当前的配置优先级为准。
- 修改 `.env` 或环境变量后，停止并重新启动服务。

## 3. 启动、验证与停止

### 后台启动

```bash
./scripts/start.sh
```

默认访问：`http://127.0.0.1:8710`。

默认日志：`/tmp/charvar-web-8710.log`，端口变化时日志文件名随之变化。

验证服务：

```bash
curl -s --noproxy '*' http://127.0.0.1:8710/api/version
```

应返回包含应用名称与版本的 JSON；具体版本号以当前代码为准。

### 停止或更换端口

```bash
./scripts/stop.sh
./scripts/stop.sh 8799
CHARVAR_WEB_PORT=8799 ./scripts/start.sh
```

`CHARVAR_WEB_PORT` 的启动脚本用法是 shell 环境变量，如上所示。

### 前台运行与调试

```bash
.venv/bin/python -m web.app
```

开发时如需热重载，可先停止已有服务，再执行：

```bash
.venv/bin/python -m uvicorn web.app:app --reload --host 127.0.0.1 --port 8710
```

说明：

- 本指南采用本机回环地址，不涉及公网部署。
- 普通后台启动不启用代码热重载。
- 修改 Python 代码、`.env` 或环境变量后需重启；仅修改静态前端文件时通常刷新页面即可。
- 未配置出图后端，不应作为网页启动失败的判断依据。

### 4.2 导入已经准备好的本地数据

以下是项目已有的导入命令入口。执行前，先按对应库文档及导入器要求准备本地目录、图片和必要元数据；这些命令不是任意图片目录的通用导入说明。

仅执行已经准备好对应数据的项目：

```bash

.venv/bin/python -m charvar.cli costume import
```

本地导入命令的存在不授予素材获取或使用权限，也不要求用户先下载完整第三方图库。

### 4.3 仓库中的下载脚本

下载脚本不是基础安装或启动的必需步骤，本指南不将其作为上述第三方图库的默认获取流程。

仅可在来源允许相应获取方式，或使用者已取得必要许可的范围内使用下载工具。对于明确禁止批量下载或自动获取的来源，请勿运行此类操作。

脚本存在、由用户主动执行或文件仅保存在本地，均不表示相应来源已授权该获取方式，也不表示项目软件许可证授予了第三方素材权利。

### 4.4 自建服饰条目

项目已有自建服饰条目的导入入口，可按需执行：

```bash

```

相关条目位于 `presets/costumes/studio/`；数量及内容以当前仓库为准。

### 4.5 未初始化时的提示

未导入素材时，姿势、服饰或人脸页面可能显示空列表、未初始化提示或返回错误。这不代表整个服务部署失败。

如果现有界面或错误信息仍列出下载脚本命令，该提示不构成来源授权，也不应覆盖本节的使用限制。已有本地数据时，按对应导入器要求处理；没有获准素材时，可以跳过相关图库功能。

## 5. 首次部署检查清单

完成第 1–3 节后检查以下项目。第 4 节为可选素材导入，不作为基础部署成功的条件。

### 基础服务

- [ ] `.venv/bin/python --version` 与预期一致。
- [ ] `curl -s --noproxy '*' http://127.0.0.1:8710/api/version` 有正常响应。
- [ ] 浏览器可打开 `http://127.0.0.1:8710`。
- [ ] 页面可以正常切换，日志中没有阻止服务运行的异常。
- [ ] 未配置后端或未导入图库时，能区分功能未就绪与基础服务故障。

### 可选功能

- [ ] 使用 ComfyUI 时，检查 `/comfy/status`；连接失败时核对地址、端口及网络。
- [ ] 使用在线 API 时，确认密钥、模型 ID 和余额／配额。
- [ ] 使用即梦时，在运行服务的同一环境中检查 CLI 与登录状态。
- [ ] 使用全局 CLI 时，执行 `~/.local/bin/charvar --help` 检查；若使用短命令 `charvar`，确认 `~/.local/bin` 在 PATH 中。
- [ ] 使用 Claude skills 时，确认 `~/.claude/skills/charvar-skill` 与 `character-forge` 的安装或软链状态。
- [ ] 按需检查已合法准备的本地素材导入结果，无需初始化全部图库。

### 测试

```bash
.venv/bin/python -m pytest -q
```

若测试工具未安装，按项目当前开发依赖说明安装。测试失败时应结合当前代码与报错分析，不要仅凭本指南的历史记录判断原因。

## 6. 可选后端：即梦 Dreamina

即梦通路使用运行环境中的 CLI。安装与授权方式请核对官方当前说明，以下保留项目原部署文档使用的入口供确认：

```text
https://jimeng.jianying.com/cli
```

不要未经检查就将远程脚本直接交给 shell 执行。确认来源与内容后，按官方当前步骤安装。

```bash
command -v dreamina
```

如果服务找不到 CLI，可按项目配置要求设置 `DREAMINA_CLI` 的绝对路径。配置后重启服务。

提示词长度、参数能力、鉴权流程及 CLI 版本可能变化，以当前项目校验逻辑和官方说明为准。

## 7. 常见问题与历史排查记录

### 7.1 启动失败或模块缺失

查看日志：

```bash
tail -n 100 /tmp/charvar-web-8710.log
```

如使用其他端口，请替换日志文件名。

排查顺序：

1. 确认当前目录为项目根目录。
2. 确认 `.venv/bin/python` 存在。
3. 使用 `.venv/bin/python -m pip install -r requirements.txt` 安装依赖。
4. 检查端口是否已被其他进程使用。
5. 停止旧服务后重新启动。

项目历史上曾出现缺少 `python-multipart`、启动脚本使用错误解释器及 CLI launcher 路径失效等问题。再次出现类似症状时，仍应以当前日志为依据，不要假定所有错误具有相同原因。

### 7.2 依赖装到了系统 Python

统一使用明确的虚拟环境路径：

```bash
.venv/bin/python -m pip --version
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
```

不要仅凭终端显示的环境名称判断依赖安装位置。

### 7.3 图库页面为空或提示未初始化

这是可选本地素材未就绪的情况，见第 4 节。不要因此把第三方整库下载当作修复基础服务的必需操作。

如已经准备好本地素材，检查目录、元数据格式及导入结果；具体要求见对应库文档。

### 7.4 即梦 CLI 不可用

未安装、未登录或服务进程找不到 CLI 时，即梦实际生图通路不可用。无需使用即梦时，可以跳过，不影响其他已经正确配置的后端。

单元测试是否依赖本机 CLI 应以当前测试实现为准，不将“未安装 CLI”一概视为测试失败原因。

### 7.5 配方引用的预设不存在

项目历史记录中，`presets/recipes/stockings_showcase.yaml` 曾涉及将服饰家族 `stockings_8` 作为动作预设引用的问题。

如果当前仍出现类似报错，请区分动作预设、服饰家族和运行时数据库条目，按当前配方语义检查引用。不要未经核实就通过下载第三方图库来修复引用问题。

### 7.6 依赖版本冲突

优先使用本项目独立虚拟环境，不要与 Selenium 等其他项目共用环境。

如遇 `typing-extensions`、FastAPI 等版本冲突，先检查实际依赖：

```bash
.venv/bin/python -m pip check
.venv/bin/python -m pip show fastapi typing-extensions selenium
```

根据当前依赖约束处理，不要直接照搬历史版本组合或在系统环境中盲目降级。

### 7.7 内网请求受到代理影响

连接 ComfyUI 等内网服务时，检查 `ALL_PROXY`、`HTTP_PROXY`、`HTTPS_PROXY` 等变量。

命令行排查可使用：

```bash
curl --noproxy '*' http://127.0.0.1:8188/
```

如 ComfyUI 在其他主机，请替换地址与端口。自行编写客户端时，也需明确是否继承环境代理。
