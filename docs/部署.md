# 部署指南（全新克隆 → 跑起来）

给刚拿到这份仓库的人：**照着这五步走，服务就能在 http://127.0.0.1:8710 起来**。
README 的「安装 / 启动」段是最小命令，本文件是完整版：含前置条件、配置项、
可选数据初始化、以及踩过的坑。

---

## 0. 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| Python | ≥ 3.11 | 实测 3.12.8；项目不挑小版本，但 3.11 以下没测过 |
| screen | 必需 | macOS 自带；Linux 需 `apt install screen`，否则 `start.sh` 里的后台会话起不来 |
| ffmpeg | 可选 | 只有「配方合成视频」这条链路要 |
| 磁盘 | 建议留 5–10 Gi | 参考库图片数据是运行时产物，不进 git，要单独下（见第 4 步） |

出图后端三选一（不配也能开网页，只是出不了图）：
- **ComfyUI**：`COMFYUI_HOST` / `COMFYUI_PORT`（本机或局域网）
- **OpenRouter**：`LLM_API_KEY`（LLM 改写 + 在线生图共用一把 key）
- **即梦 Dreamina**：本机官方 CLI，无 API Key，需手动浏览器授权（见第 6 节）

## 1. 建虚拟环境 + 装依赖

```bash
cd /path/to/charvar
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

**为什么要建 venv**：仓库里的 `scripts/install_cli.sh` 生成的全局 CLI
（`~/.local/bin/charvar`）与 `scripts/start.sh` 都按「仓库内 `.venv`」找解释器。
不建 venv 时 CLI 会指向不存在的 `.venv/bin/python` 而直接不可用
（launcher 现在会退回系统 `python3`，但版本可能对不上，仍建议建 venv）。

`requirements.txt` 已包含全部运行时依赖（含 `python-multipart` ——
上传接口要用它，缺了会在 app 构建阶段就崩，服务根本起不来）。

## 2. 配 `.env`

```bash
cp .env.example .env
# 编辑 .env：至少填 LLM_API_KEY（要 LLM 改写/在线生图时）
```

`.env` 不进 git。**改完 `.env` 必须重启服务**（没有热重载，环境变量只在启动时读）。
完整键位见 `.env.example` 的注释。

## 3. 启动

```bash
./scripts/start.sh          # 后台起（screen 会话 charvar-8710）
```

- 启动器优先用 `.venv/bin/python`，没有 venv 才退回系统 `python3`
- 只监听 `127.0.0.1`，不对外网开放
- 日志：`/tmp/charvar-web-8710.log`（端口跟随 `CHARVAR_WEB_PORT`）

验证：

```bash
curl -s --noproxy '*' http://127.0.0.1:8710/api/version
# {"app":"charvar","version":"0.1.0"}
```

停止 / 换端口：

```bash
./scripts/stop.sh                          # 停默认端口
./scripts/stop.sh 8799                     # 停指定端口
CHARVAR_WEB_PORT=8799 ./scripts/start.sh   # 换端口多开
```

> **没有热重载**：改了 `charvar/**`、`web/app.py` 或环境变量后必须停再起；
> 只改 `web/static/**` 刷新页面即可。

## 4. 参考库初始化（可选，但没它三个库页是空的）

姿势库 / 服饰库 / 人脸库的图片数据**不随 git 分发**（`data/poses/`、
`data/costumes/`、`data/faces/` 都在 `.gitignore` 里），每个库都是两步：
**下载脚本 → CLI 灌库**。

```bash
# 姿势库（线稿 pose-db-01；深度图 pose-db-02 加 --source pose-db-02）
python3 scripts/download_pose_db.py
.venv/bin/python -m charvar.cli pose import

# 服饰库
python3 scripts/download_costume_db.py
.venv/bin/python -m charvar.cli costume import

# 人脸库（站方已停止分发图像数据，仅本机自用；含发型档，体积大）
python3 scripts/download_face_db.py
.venv/bin/python -m charvar.cli face import
```

脚本幂等：文件在且魔数对就跳过，重跑即续传。

**自建服饰条目**走另一条路（镜像在 `presets/costumes/studio/`，28 条）：

```bash
.venv/bin/python -m charvar.cli costume import-studio
```

三个库没初始化时的表现（**不是故障**）：
- `/ui/poses` 空网格，文案提示「姿势库还没初始化」并给出上面两条命令
- `/ui/costumes`、`/ui/faces` 报 404，detail 里写明「先跑 scripts/download_*.py 下载，再 charvar X import 灌库」

> 服饰库那 1407 条含 1366×2048 无损 PNG，体积可观；下之前先看一眼磁盘余量。

## 5. 首次部署检查清单

跑完上面四步，按这张单子过一遍：

- [ ] `curl http://127.0.0.1:8710/api/version` 有响应
- [ ] 浏览器打开 http://127.0.0.1:8710 ，顶栏页签能切（预设 / Playground / 视频 / 语音 / 姿势 / 服饰 / 人脸 / 运行 / 设置）
- [ ] `/comfy/status` 返回 `ok: true`（用了 ComfyUI 的话；连不上说明网络或地址不对）
- [ ] `~/.local/bin/charvar --help` 有输出（`start.sh` 会顺带装；换终端可能要 `source ~/.zshrc`）
- [ ] `~/.claude/skills/charvar-skill` 与 `character-forge` 软链已建
- [ ] 跑一次测试确认环境完整：`python3 -m pytest -q`

## 6. 可选后端：即梦 Dreamina

即梦走本机官方 CLI（子进程，不是 HTTP），**没有 API Key 可配**，鉴权是本机的登录态：

```bash
curl -s https://jimeng.jianying.com/cli | bash   # 装 CLI
dreamina login                                # 浏览器里手动完成授权
```

授权必须自己点 —— 代跑可能拿到错误回调 URL（官方文档有「非法应用」案例）。
CLI 找不到时用 `DREAMINA_CLI` 指绝对路径。

即梦不暴露 seed，也不区分文生图/图片编辑的配置组；提示词有硬上限
（text2image 1592 字符 / image2image 1992 字符），超了提交前就被拒。

## 7. 已知问题

### 7.1 本仓库已修（2026-10-31 部署时发现）

| 现象 | 根因 | 处理 |
|---|---|---|
| `start.sh` 报「启动失败」，日志 `RuntimeError: Form data requires "python-multipart"` | `requirements.txt` 漏列 `python-multipart`，上传接口在 app 构建阶段就抛错 | 已补进 `requirements.txt` |
| `~/.local/bin/charvar` 报 `No such file or directory: .venv/bin/python` | launcher 硬指向仓库 venv，全新克隆没有 venv 就整个 CLI 不可用 | launcher 改为「有 venv 用 venv，没有退回系统 `python3`」 |
| `start.sh` 起的进程用的不是仓库 venv（装了依赖也白装） | 脚本硬编码 `python3`，而 screen 里的 `zsh -lc` 登录 shell 会重建 PATH，注入的 venv 路径被冲掉 | `start.sh` 改为显式指向 `.venv/bin/python`（没有才退回 `python3`） |
| `pytest` 10 个 `test_dreamina_image.py` 用例红 | 用例只打桩了 `subprocess.run`，没打桩解释器解析 → 机器上没装 dreamina CLI 就整组失败 | fixture 里打桩 `resolve_binary`（真实解析另有 `test_binary_env_override` 覆盖） |
| `pytest` 1 个 `test_recipe_preset_refs_resolve` 用例红 | 配方引用服饰家族 `stockings_8`，而服饰家族名取自运行时 DB；**全新克隆没灌库时 DB 为空 → 误判成「预设不存在」** | 校验时并上仓库镜像 `presets/costumes/studio/` 里的家族名，不再依赖运行时 DB 状态 |

### 7.2 要用户自己处理的

| 事项 | 影响 | 怎么办 |
|---|---|---|
| 即梦 CLI 没装 | 10 个 dreamina 测试红；即梦通路不可用 | 见第 6 节 |
| 三个参考库没初始化 | 姿势/服饰/人脸三页空 | 见第 4 节 |
| `presets/recipes/stockings_showcase.yaml` 第 2 步引用服饰家族 `stockings_8` | 该配方运行时会因「预设不存在」失败（**上游内容 bug**，非部署问题） | 该步的 `presets` 应只挂动作预设；家族名不是动作预设，需按配方语义改写 |

### 7.3 环境相关的坑

- **依赖装到了系统 Python 而非 venv**：`pip install -r requirements.txt` 不带
  路径会装到当前解释器。确认 `which python3` / `python3 -m pip --version` 的落点。
- **typing_extensions 版本冲突**：fastapi 新版要 `typing-extensions>=4.15`，
  而 selenium 要 `~=4.14.0`。两者共存时把 fastapi 钉到 0.115.x、
  `typing-inspection` 钉到 0.4.1（`pip install "fastapi==0.115.6" "typing-inspection==0.4.1" "typing-extensions==4.14.1"`）。
- **ComfyUI 走内网地址**：本机 shell 的 `ALL_PROXY` 会劫持内网请求，
  项目内已统一 `trust_env=False` 绕过；自己另写脚本调内网时注意这点。
